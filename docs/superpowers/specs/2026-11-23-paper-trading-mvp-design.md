## 0. 一句话定义

用**真实 A 股数据**、**虚拟资金**、**收盘后按官方开盘价结算的纸面成交**，每天生成可追溯的决策卡，按固定规则模拟买卖并逐日对账，用可复现的实验协议检验这套投研方法是否值得继续投入——全程不接券商、不碰真钱、不构成投资建议。

---

## 1. 为什么做、做到什么程度

### 1.1 要解决的问题

当前产品已经能看收盘简报、行业判断、自选、持仓、论点和任务，但用户仍无法回答三个关键问题：

1. 这些判断如果当时真的执行，结果会怎样？
2. 亏损是因为判断错了，还是因为买贵了、卖晚了、仓位重了？
3. 这套方法连续运行几个月后，是否比“什么都不做”更好？

模拟盘不是增加一个“炒股功能”，而是给现有研究加一条**可验证的闭环**：判断 → 决策卡 → 用户确认 → 纸面委托 → 收盘后结算 → 持仓 → 复盘 → 评估。

只回答第 1 个问题不够。系统建议和用户实际执行必须分开记账、分开展示，否则无法区分“方法有效”与“用户纪律”。

### 1.2 产品边界（本期）

**做：**

- 真实行情、真实公告、真实交易日历；虚拟现金与虚拟持仓。
- 收盘后生成次日决策卡；用户在截止前显式确认；收盘后用官方开盘价结算。
- 纸面账户、委托、成交、持仓、现金流水、每日净值、每日对账。
- 与实验绑定的影子组合：系统按同一规则执行所有已触发卡，用于和方法本身对比。
- 风控检查、持仓风险扫描、每日/每周复盘。
- 与全收益指数、现金、等权自选对比的有效性指标。
- 所有判断可追溯到不可变快照、证据、规则版本。

**不做：**

- 不接券商、不发送真实委托、不管理真实资金。
- 不做盘中决策、盘中触发、分钟级自动交易、T+0。
- MVP 不做限价单、不做止损单；所有成交都在开盘价上结算。
- 不做融资融券、卖空、杠杆、期权期货。
- 不让 LLM 直接决定买什么、买多少；LLM 只做证据归纳和情景解释。
- 不承诺收益，不输出“必涨/必跌”，不把模拟结果包装成实盘业绩。
- 不做公开荐股、组合跟单、社区排行。

### 1.3 与现有产品定位的衔接

现有定位是“政策-行业影响分析引擎”，强调研究、信息准备、证据可追溯。模拟盘是它的**验证层**，不是另一套荐股产品：

- 决策卡必须能回到“政策/行业/公司事件 → 价格与流动性确认 → 风险与反证”的证据链。
- 决策卡的结论是“研究性操作提案”，不是投资建议。
- 模拟盘页面固定展示“虚拟资金，不是真实持仓；不构成投资建议”。

### 1.4 成功标准

MVP 的成功不是“赚了多少钱”，而是：

1. **过程可信**：每一笔纸面成交都能解释清楚——哪张卡、哪个版本、什么证据、什么规则、哪个官方价格、什么费用、何时结算。
2. **数据可信**：不使用未来数据，不混用示例数据，缺数据时显式降级而不是猜；标的元数据、涨跌停价、停复牌、公司行动可追溯。
3. **账本可信**：账本可从仅追加事件重建；每日对账四条恒等式全部成立；崩溃后重放不重复成交。
4. **用户能懂**：新手能在 30 秒内看懂“今天该不该动、为什么、最坏亏多少”；能分清“系统判断”和“我的执行”。
5. **可评估**：一个实验跑满 120 个有效交易日、最后一张卡满足 60 日观察窗、且至少 30 张触发卡后，能给出扣费后的超额、回撤、命中率与执行偏离，而不是只给一条净值曲线。

## 2. 用户与核心场景

### 2.1 用户

- 主要用户：有 A 股账户、但缺少系统研究流程的个人投资者；能看懂涨跌和市盈率，不熟悉机构术语。
- 使用方式：每天盘前 5 分钟、盘后 10 分钟；周末 20 分钟复盘。
- 设备：手机优先，桌面增强；本地数据优先，不依赖云服务。

### 2.2 核心任务（JTBD）

| 场景 | 用户想完成的事 | 模拟盘要给出的答案 |
|---|---|---|
| 盘前 | 今天要不要动？ | 已确认的委托、待确认的触发卡、数据质量与风险状态；默认“不操作” |
| 盘中 | 有没有需要处理的？ | 只读风险提示；不产生委托、不判定成交；明确“已确认，待收盘确认” |
| 盘后 | 今天做对了没有？ | 官方开盘价结算结果、净值变化、对账状态、是否违反计划 |
| 周末 | 这套方法靠谱吗？ | 系统判断 vs 我的执行、执行率与偏离原因、样本是否足够 |
| 任意时刻 | 为什么买/为什么没买？ | 决策卡 + 证据 + 不可变快照 + 规则版本 |

### 2.3 新手行为约束

- 默认不操作；没有明确触发条件和数字止损，就没有可执行买入卡。
- 一笔委托必须展示：买什么、为什么、买多少、最多亏多少、费用多少、什么时候复核。
- 不允许“一键全仓”“一键跟单”“自动加仓”。
- 列表页不提供“直接买入”；执行必须进入详情页，看过风险信封后再确认。
- 术语第一次出现时给一句人话解释；详细解释放抽屉，不打断主任务。
- 任何“系统建议”旁边必须有证据分和反证，不能只给结论。

## 3. 验证阶梯与阶段门

模拟盘只是第二级，不允许跳级。

| 级别 | 内容 | 时长/样本 | 通过后才能进入 |
|---|---|---|---|
| L0 历史回放 | 用历史数据回放同一套规则，检查前视、幸存者偏差、成本遗漏、延迟成交 | ≥50 只股票、≥5 年；含 2015/2018/2022 压力区间；成本翻倍、成交延迟一天 | L1 |
| L1 前向纸面 | 真实数据、虚拟资金、每日运行，规则冻结 | 120 个有效交易日 + 最后一张卡满 60 日观察窗 + ≥30 张触发卡 | L2 |
| L2 券商沙盒 | 券商模拟环境，验证委托、成交、撤单、对账接口 | 1–3 个月；累计样本达到绩效门槛 | L3 |
| L3 小资金实盘 | 极小资金，人工确认每笔，严格风控 | 3–6 个月 | L4 |
| L4 全自动 | 分析、决策、执行、复盘全自动，保留总开关 | 持续 | — |

**阶段门规则：**

- L0 是 L1 的入场券，不是可选项。没有 L0 回放报告，不启动 L1 计时。
- L1 → L2 是**过程与完整性门**：账本、对账、PIT、数据质量、用户确认链路可信即可；绩效只观察，不单独作为进入 L2 的依据。
- L2 → L3 是**绩效与校准门**：必须在 L1+L2 累计 ≥250 个有效交易日、≥100 张触发卡，且校准状态为 `calibrated`；样本不足就延长 L2，不缩短门槛。
- 每一级开始前锁定规则版本、资金规模、评估窗口、通过阈值；开始后不许移动球门。
- 任何规则、参数、费用假设的修改都产生新版本，并重新计时；旧版本结果保留，不覆盖。
- 前视审计失败、对账不平衡、合规缺项是二值否决项；不参与加权总分计算。
- L1 出现以下任一情况直接不通过：使用未来数据、账本对不上、示例数据混入、风控被绕过、无法解释的成交、盘中用延迟报价成交。

## 4. 每日运行闭环

### 4.1 时间表（Asia/Shanghai，交易日）

| 时间 | 任务 | 产出 | 失败时 |
|---|---|---|---|
| 前一日 17:30 | 生成次日决策卡 | 0–5 张卡；每张含证据、触发、证伪、数字止损、仓位、复核日、快照 | 任务失败可见；不补造卡片 |
| 08:30 | 盘前复核 | 隔夜外盘、公告、新闻、交易日历、数据质量；只允许降级/撤销已有卡，不新增买入卡 | 标记降级；关键数据缺失则冻结当日新确认 |
| 09:15 | 确认截止并冻结 | 已确认委托进入 `settlement_pending`；冻结现金/股数；未确认卡转 `expired` | 截止后拒绝新确认（`TOO_LATE`） |
| 09:30–11:30 / 13:00–15:00 | 只读监测 | 延迟报价、风险提示、数据延迟；不产生委托、不判定触发、不成交 | 标注 `stale`；不影响结算 |
| 16:10 | 官方日线入库 | 日线、涨跌停价、成交额、停复牌、复权因子 | 缺数据则当日结算挂起，状态 `MISSING_PRICE` |
| 16:20 | 结算回填 | 用官方开盘价结算用户委托；结算影子组合；持仓风险扫描；公司行动 | 缺开盘价不成交，不顺延、不用盘中价替代 |
| 16:30 | 对账与净值 | 四条恒等式、净值、基准、风险状态 | 账本不平衡触发 kill switch；缺价只标 `MISSING_PRICE` |
| 17:00 | 每日复盘 | 成交、净值、对账、违规、异常、次日待办 | 生成失败可在任务中心重跑 |
| 周六 10:00 | 周度复盘 | 周收益、超额、回撤、执行率、偏离原因、数据质量 | 生成失败可重跑 |

**关键时点说明：**

- Tushare 日线在当日 16:00 后才稳定；因此**任何成交都不得早于 16:10**。
- 09:30–15:00 的延迟报价只用于风险提示和单日亏损拦截，**绝不用于成交**。
- 16:20 结算时，成交价取目标交易日官方日线的 `open`；`trade_time` 记为 `09:25`（集合竞价时点），`settled_at` 记为实际结算时间，`price_basis='official_daily_open'`。UI 在 16:20 前显示“已确认，待收盘确认”，不显示“已成交”。
- 缺官方开盘价时，委托转 `expired(MISSING_PRICE)`；账户进入 `MISSING_PRICE` 风险状态（禁止新买入），直到数据补全并人工确认，不冻结已有持仓的估值展示。

**休市日：** 不生成卡、不结算、不估值；页面显示“今日休市”，而不是空白或昨日数据。

### 4.2 决策节奏（MVP 只做一种）

**T 日收盘后决策，T+1 日开盘结算。**

- 卡在 T 日 17:30 生成，`as_of` 为生成时刻，只使用 T 日已发布的官方数据与当时可见的公告。
- 用户在 T+1 日 09:15 前显式确认；09:15 后截止。
- T+1 日 16:20 用 T+1 官方开盘价结算。
- 盘前 08:30 只复核，不新增买入卡。隔夜重大事件只能让已有卡降级、撤销或触发证伪，不能临时造一张新卡去追。
- 不做盘中决策。用户盘中记录的想法只能进日志，不能生成委托。

**为什么不做“盘前决策、当日开盘执行”：** 08:30 到 09:15 只有 45 分钟，无法完成公告抓取、数据质量校验、证据复核和用户阅读；强行加入会让“发卡”和“确认”挤在同一时段，诱发拍脑袋确认。

### 4.3 卡片与委托状态

**卡片状态：**

| 状态 | 含义 | 新手文案 |
|---|---|---|
| `active` | 等待触发 | “等条件满足” |
| `triggered` | 触发已满足，等待用户确认 | “可以动手，等你确认” |
| `confirmed` | 用户已确认，等待收盘结算 | “已确认，待收盘确认” |
| `executed` | 已成交 | “已成交” |
| `not_triggered` | 观察窗口结束仍未触发 | “条件没出现，作废” |
| `invalidated` | 触发了证伪条件 | “逻辑被证伪，取消” |
| `expired` | 截止前未确认或未成交 | “过期，不执行” |
| `dismissed` | 用户主动忽略（需填原因） | “你选择忽略” |

**委托状态：** `confirmed` → `settlement_pending` → `filled` / `rejected` / `expired` / `trigger_not_met` / `canceled`。详见 §7.4。

### 4.4 补跑边界

- 补跑只允许补：行情入库、估值、对账、复盘、结果评估。
- 补跑**绝不补造** 09:15 后的决策卡、用户确认或成交。
- 缺日标记 `quality='gap'`；有效交易日计数跳过 `gap`，并在实验报告中列出缺失日期。
- 追赶器不得把多天委托合并到一天结算；错过结算窗口的委托按 `expired` 处理。

### 4.5 默认动作

- 没有满足条件的标的：明确显示“今天不操作”，并给出原因（市场状态、数据质量、风险预算）。
- 有卡但未触发：显示“等待触发”，不提前下单。
- 触发但风控不通过：显示“被风控拦截”，给出具体规则和复核入口。
- 用户不确认：不成交。MVP 每笔纸面委托都需要用户明确确认；没有自动转委托。

## 5. 数据架构

### 5.1 三层数据，各司其职

| 层 | 内容 | 用途 | 能否触发成交 |
|---|---|---|---|
| 权威事实层 | 交易所公告、巨潮公告、证监会政策、Tushare 日线/日历/复权因子/分红送转、交易所涨跌停价、停复牌 | 决策、结算、估值、对账 | 是（仅收盘后已发布数据） |
| 盘中监测层 | 新浪/腾讯/东财等延迟行情、涨跌停统计、成交额 | 盘中提示、单日亏损拦截 | **否**（MVP 不用于成交） |
| 研究叙述层 | 新闻、LLM 归纳、行业分析、情景解释 | 证据补充、人话解释 | **否**（不能单独成为买入理由） |

**关键原则：**

- 决策和成交只认权威事实层；盘中报价必须标注来源、时间、延迟秒数。
- 新闻只能作为证据之一，不能单独触发交易。
- 任何一层缺失，都要在卡片和页面显式标注，不允许用另一层“补一个看起来合理的数”。

### 5.2 MVP 数据源清单

| 数据 | 首选来源 | 层级 | 频率 | 备注 |
|---|---|---|---|---|
| 交易日历 | Tushare `trade_cal` | T1 | 每日 | 必须覆盖未来 370 天；不足则数据质量 `fail` |
| A 股日线（未复权） | Tushare `daily` | T1 | 每日 16:10 | 结算与估值用未复权价 |
| 复权因子 | Tushare `adj_factor` | T1 | 每日 | 绩效与回测用复权价；禁止硬编码为 1 |
| 每日指标（换手、量比、市值） | Tushare `daily_basic` | T1 | 每日 | 流动性过滤 |
| 涨跌停价 | 交易所公开数据 / Tushare `stk_limit` | T0/T1 | 每日 | 必须按板块与 ST 状态取；缺失即 `fail`，不默认 10% |
| 停复牌 | Tushare `suspend_d` / 交易所公告 | T1/T0 | 每日 | 停牌不成交 |
| 分红送转 | Tushare `dividend` / 交易所公告 | T1/T0 | 事件驱动 | 股权登记日、除权除息日、派息日都要保存 |
| 股票基本信息 | Tushare `stock_basic` / 交易所 | T1 | 每周 | 板块、上市日、退市日、ST 状态 |
| 公告 | 上交所、深交所、巨潮 | T0 | 每 10 分钟游标拉取 | 保存标题、链接、发布时间、原文 hash |
| 政策 | 证监会、央行、统计局、发改委 | T0 | 事件驱动 | 保存原文链接与发布时间 |
| 新闻 | 财联社、新浪 7×24、华尔街见闻 | 研究层 | 事件驱动 | 只作证据，不作成交依据 |
| 盘中延迟报价 | 新浪/腾讯批量接口 | 监测层 | 30–60 秒 | 标注延迟；只用于风险提示 |
| 隔夜外盘 | CBOE 延迟 | 研究层 | 每日 | 只作背景 |

**数据许可与合规：**

- 免费源不等于可自由再分发；本项目只做个人本地研究，不对外提供数据 API、不转售、不公开展示原始行情。
- 每个源在 `source_registry` 记录 `terms_url`、启用状态、最近成功时间、连续失败次数、限流参数。
- 被封 IP、限流、条款变化时，宁可停用并显示降级，不绕过限制。
- 公告抓取使用 `last_seen_published_at` 游标；30 分钟 SLA 改为“尽力而为”，卡上标注公告截止时间。

### 5.3 标的元数据与股票池

现有 `symbols` 表字段不足，必须新增：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `symbol_meta` | `code`, `board`（主板/创业板/科创板）, `is_st`, `list_date`, `delist_date`, `limit_rule_version`, `effective_from`, `effective_to`, `source_id` | SCD2 历史；状态变化用新行，不改旧行 |
| `symbol_industry_history` | `code`, `industry_l1`, `effective_from`, `effective_to`, `source_id` | 行业归属历史，避免用今天的行业回填历史 |
| `limit_price_daily` | `trade_date`, `code`, `limit_up_cents`, `limit_down_cents`, `source_id`, `fetched_at` | 每日涨跌停价；未知不默认 10% |
| `paper_universe` | `experiment_id`, `as_of`, `code`, `source`, `reason`, `added_at`, `removed_at` | 实验股票池成分快照；决策只认当时成分 |

**股票池规则：**

- 最多 50 只：用户自选 ∪ 系统候选 ∪ 当前持仓（持仓必须纳入，否则无法生成退出卡）。
- 仅沪深主板、创业板、科创板；排除北交所、ST/*ST、退市整理、上市不足 60 个交易日、ADV 不足。
- 每个标的必须能取到板块、ST 状态、上市日、涨跌停规则；任一未知，该标的当日 `DATA_QUALITY fail`，不生成卡、不成交。
- 用户手动加入的标的也要经过同一套质量门；不能“因为是我加的”绕过。

### 5.4 不可变快照（PIT）

现有 `fact_snapshots` 只保存引用，不足以证明“决策当时到底看到了什么”。新增 `paper_snapshots`，保存**决策实际使用的精确事实**：

```
snapshot_id
as_of                  决策时点（含时区）
trade_date             决策针对的交易日
universe_json          本次扫描的股票池及成分来源
dataset_version        数据集版本号
source_manifest_json   每个数据源的版本/时间/状态
quality_json           完整性、时效、一致性、来源质量
facts_json             每只相关标的的精确事实：
                       OHLCV、adj_factor 及版本、涨跌停价及来源、
                       停牌状态、行业归属、上市日、ST 状态
content_hash           内容哈希，防篡改
created_at
```

**PIT 规则：**

- 只用 `published_at <= as_of` 的公告和新闻；`effective_at` 晚于决策时点的政策不得提前使用。
- 行情只用截至上一收盘已发布的数据；不得使用当日收盘价做当日开盘决策。
- 财务数据用公告日，不用报告期；未公告的财报不得进入快照。
- 股票池使用决策时点的成分，不得用今天的指数成分回填历史。
- 退市股保留在历史库中；不得为了“回测好看”删除退市样本。
- 每张卡保存 `snapshot_id`；快照生成后不可修改，只能新建版本。
- `market_bars` 的 `ON CONFLICT DO UPDATE` 只允许修正同一 `source_id` 的抓取错误，并记录修正前后 hash；不同来源的数据必须分行，不得静默覆盖。

**前视审计：**

- 自动测试：注入一条 `published_at` 晚于 `as_of` 的公告，决策结果不得变化。
- 自动测试：注入一条未来 K 线，回测/评估结果不得变化。
- 自动测试：修改快照生成之后才发布的涨跌停价/停牌状态，历史成交与评估不得变化。
- 每次规则变更后重跑审计；审计失败阻止发布决策卡。

### 5.5 数据质量门

| 状态 | 含义 | 对决策/成交的影响 |
|---|---|---|
| `pass` | 关键数据齐全、时效达标、来源一致 | 正常 |
| `warn` | 非关键数据缺失或轻微延迟 | 可生成卡，但卡上必须显示警告；用户确认后才能下单 |
| `fail` | 关键数据缺失、过期、冲突、示例数据混入 | **禁止生成新卡、禁止成交**；页面显示原因与修复入口 |

**关键数据（fail 级）：** 交易日历、目标股当日/前日行情、涨跌停价、停牌状态、标的元数据、账户现金、规则版本。
**非关键数据（warn 级）：** 新闻、外盘、行业分类、部分公告。

**时效阈值（可配置，默认）：**

- 日线：交易日 16:10 前必须入库；否则当日结算挂起，状态 `MISSING_PRICE`。
- 公告：决策时点前 30 分钟内发布的公告尽量抓取；未抓到的，卡上标注公告截止时间，不假装已覆盖。
- 盘中报价：超过 120 秒未更新，标 `stale`，只用于风险提示，不用于任何成交或触发判断。

### 5.6 示例数据隔离

- 延续现有 `assertNoDemoData`：一旦库中存在示例数据，禁止接入真实行情；模拟盘也不得在示例库上运行。
- `paper_accounts`、`paper_orders`、`paper_fills`、`paper_nav`、`paper_snapshots` 必须带 `is_demo` 标志；UI 固定显示“示例数据”水印。
- 测试夹具与生产数据分库；不得用“清空表”方式混用。

### 5.7 数据源适配器契约

所有外部数据必须经过统一适配器，禁止在业务代码里直接 `fetch`：

```ts
interface SourceAdapter<T> {
  id: string                    // 与 source_registry.id 对应
  tier: 'T0' | 'T1' | 'monitor' | 'research'
  schemaVersion: string
  license: { termsUrl: string; redistributable: false }
  rateLimit: { perMinute: number; burst: number }
  timeoutMs: number
  fetch(cursor: string | null): Promise<{ rows: T[]; nextCursor: string | null }>
}
```

- 进程级令牌桶 + 指数退避 + 抖动 + 熔断（连续失败 5 次暂停 30 分钟）。
- 每个适配器有离线夹具契约测试：字段、单位、时区、空值语义、分页游标。
- 新浪/腾讯批量请求，单次最多 50 个代码；不得逐只轮询。
- 任何适配器返回未知枚举/缺字段，直接 `DATA_QUALITY fail`，不猜默认值。

## 6. 决策卡

### 6.1 定义

决策卡是“一份可执行、可证伪、可复盘的研究结论”。它不是新闻摘要，也不是 LLM 的自由文本。

**一张卡只回答五个问题：**

1. 看什么？（标的、周期）
2. 现在是什么立场？（观察/候选/谨慎/回避）
3. 为什么？（支持证据 + 反证）
4. 什么条件下动手？（触发，必须可机器判定）
5. 什么条件下认错？（证伪）以及最多买多少、最多亏多少、什么时候复核。

### 6.2 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 稳定 ID |
| `experiment_id` | string | 是 | 所属实验 |
| `trade_date` | date | 是 | 针对的交易日（T+1） |
| `as_of` | datetime | 是 | 决策时点（Asia/Shanghai） |
| `snapshot_id` | int | 是 | 绑定的不可变快照 |
| `card_version` | int | 是 | 卡片版本；任何影响执行的修改递增，执行时必须匹配 |
| `code` / `name` | string | 是 | 标的 |
| `horizon` | enum | 是 | `short`（5–20 日）/ `swing`（20–60 日）/ `medium`（60–120 日） |
| `stance` | enum | 是 | `observe`（观察）/ `candidate`（候选）/ `caution`（谨慎）/ `avoid`（回避） |
| `intent` | enum | 否 | `none` / `buy` / `add` / `reduce` / `exit`；只有 `candidate` 可 `buy/add`，`caution/avoid` 可 `reduce/exit` |
| `thesis` | string | 是 | 一句话结论，≤80 字，必须包含“因为…所以…” |
| `evidence` | array | 是 | ≥3 条；至少 1 条政策/行业、1 条价格/量能、1 条风险/反证 |
| `trigger` | object | 是 | `{ basis, condition_op, price_cents?, event_rule?, window }`；见 §6.3 |
| `trigger_basis` | enum | 是 | `prev_close` / `event` / `open_auction` |
| `invalidation` | object | 是 | 证伪条件；触发后卡状态转 `invalidated` |
| `stop_price_cents` | int | 买入必填 | 数字止损价；没有它不允许生成 `buy/add` |
| `max_position_pct` | number | 是 | 单票最大仓位，占组合净值比例 |
| `max_loss_pct` | number | 是 | 由 `(触发价 − 止损价) × 股数 + 费用` 计算，占净值；不是手填 |
| `max_loss_cents` | int | 是 | 与上一行同源，便于展示与核对 |
| `confidence` | int | 是 | 0–100，**证据分**：按政策版本中的输入项/权重/取整规则计算；不是涨跌概率 |
| `confidence_inputs_json` | object | 是 | 证据分的输入项与权重，供复核与重算 |
| `p_outperform` | number | 否 | 规则引擎的“跑赢基准”概率估计；未校准时只记录，不展示、不进阶段门 |
| `review_date` | date | 是 | 复核日；到期必须复核 |
| `policy_version` | string | 是 | 规则/风控/费用版本 |
| `status` | enum | 是 | 见 §4.3 |
| `dismissed_reason` | string | 否 | 用户忽略时必填 |
| `model_meta` | object | 否 | LLM 模型、提示词版本、耗时、成本；仅叙述层 |

### 6.3 触发语义

| `trigger_basis` | 何时判定 | 能否在 09:15 前判定 | 执行形态 |
|---|---|---|---|
| `prev_close` | 用 T 日官方收盘数据判定 | 能 | 用户确认后，T+1 开盘市价结算 |
| `event` | 用 09:15 前已发布的事件判定 | 能 | 用户确认后，T+1 开盘市价结算 |
| `open_auction` | 用 T+1 官方开盘价判定 | 不能 | 只能编码为“开盘条件单”；开盘不满足则 `TRIGGER_NOT_MET`，不成交 |

**硬约束：**

- `open_auction` 触发不允许“触发后提醒再确认”。开盘前无法知道开盘价，用户只能在 09:15 前确认一个带条件的委托；条件不满足就作废。
- 买入条件单：`open <= trigger_price_cents` 才成交；成交价 = `min(open × (1 + slippage), trigger_price_cents)`，并受涨停价约束。
- 卖出条件单：`open >= trigger_price_cents` 才成交；成交价 = `max(open × (1 − slippage), trigger_price_cents)`，并受跌停价约束。
- 条件单不是真实止损单；跳空、停牌、跌停可能让实际亏损超过计划最大亏损。UI 必须写清。

### 6.4 立场与意图的约束

| 立场 | 含义 | 允许意图 | 新手看到的文案 |
|---|---|---|---|
| 观察 | 有关注价值，但条件不成熟 | `none` | “先看着，今天不动” |
| 候选 | 证据与触发条件基本成立 | `buy` / `add` / `none` | “可以考虑，等触发再买” |
| 谨慎 | 有持仓但风险上升，或新买入不划算 | `reduce` / `exit` / `none` | “先别加，考虑减一点” |
| 回避 | 证据不足、风险过高、流动性差 | `exit` / `none` | “不碰；有持仓则考虑退出” |

**硬约束：**

- 没有 `trigger` 和 `invalidation` 的卡不能进入 `active`。
- 没有至少一条反证的卡不能进入 `candidate`。
- 没有 `stop_price_cents` 或 `max_loss_cents` 的卡不能给出 `buy/add`。
- `confidence < 50` 的卡不得给出 `buy` 意图。
- 单卡 `max_position_pct` 不得超过风控上限；超过则卡无效，不是“截断后照发”。
- 一手金额超过单票上限的标的，只能出观察卡，不能出可执行买入卡。
- 每张卡必须能一键展开到证据和快照；不能只给结论。
- 卡片任何影响执行字段的修改都递增 `card_version`；执行请求必须携带版本号，不匹配返回 409。

### 6.5 决策引擎与 LLM 的分工

**确定性引擎负责：**

- 市场状态（趋势、宽度、成交额、波动）。
- 行业相对强弱、政策事件匹配、个股趋势与流动性过滤。
- 评分、排序、仓位上限、触发价、止损价、风控检查。
- `confidence`：按政策版本中的固定输入项和权重计算，输入项必须可追溯。
- `p_outperform`：仅在有校准表时计算；没有校准表则为空，不用 LLM 自报概率。
- 生成结构化字段；同一输入 + 同一规则版本 = 同一输出。

**LLM 负责：**

- 把结构化证据归纳成 ≤80 字的人话结论。
- 解释“如果发生 X，会怎样”的情景。
- 生成复盘叙述、周报摘要。
- 不得修改评分、仓位、触发价、止损价；不得新增未在证据表中的事实。
- LLM 叙述异步生成；2 分钟超时，不阻塞卡片生成与结算。

**MVP 决策规则（透明、可复现）：**

1. **市场闸门**：指数趋势 + 市场宽度 + 成交额。市场状态为 risk-off 时，只允许减仓/回避，不生成新的买入卡。
2. **行业筛选**：政策/事件强度 + 行业 20 日相对强弱 + 行业成交额占比变化；最多选 3 个行业。
3. **个股筛选**：行业内的趋势（20/60 日均线）、量能（5 日均量/20 日均量）、流动性（20 日 ADV）、事件（公告/政策映射）；排除 ST、停牌、上市不足 60 日、ADV 不足。
4. **证据门槛**：至少 1 条政策/行业证据 + 1 条价格/量能证据 + 1 条反证；否则降为“观察”。
5. **仓位**：按波动率倒数分配，单票不超过 20%，行业不超过 40%，现金不低于 5%；按整手向下取整，一手都买不起就只给观察。
6. **触发**：突破/回踩/事件确认三类，必须写清价格或日期；未触发不下单。
7. **证伪**：跌破止损、政策逻辑被否、行业相对强弱反转、数据质量 fail；任一触发即复核。
8. **持仓覆盖**：所有持仓每日生成观察/谨慎/退出卡，不依赖行业是否入选；买入后持续监控证伪条件。

规则参数放在 `paper_policy_versions`，带生效日期和哈希；不在代码里散落魔法数字。

## 7. 纸面账户与账本

### 7.1 账户与实验

- 新增 `paper_accounts`，不复用现有 `positions` 的实盘/手工持仓。
- 每个实验一个用户账户：`paper-<experiment-id>`；另有一个影子账户：`shadow-<experiment-id>`，两者独立记账。
- 初始虚拟资金：¥200,000（实验开始后不可修改）。
- 账户状态：`active` / `paused` / `closed`；`closed` 后只读。
- 账户类型：`user`（用户确认后执行）/ `shadow`（系统按同一规则自动执行所有触发卡）。
- 现有 `portfolio_accounts` 继续服务“手动记录的真实持仓”；模拟盘页面明确区分“真实记录”和“模拟盘”，不混算。

**实验对象 `paper_experiments`：**

- 开始前锁定：协议文本、规则版本、初始资金、基准、通过阈值、计划有效天数。
- 状态：`planned` / `active` / `paused` / `closed`。
- 暂停必须写原因（数据中断、规则变更、个人原因）；暂停日不计入有效交易日。
- 重置 = 旧账户 `closed` 只读 + 新开 `-v2` 账户 + 重新计时 + `reset_count + 1`；旧结果保留，不删除、不覆盖。
- 没有新实验记录，不得重置；不得用“清空数据”冒充新实验。

### 7.2 账本原则

- 金额一律整数分；股数一律整数股；价格用分，禁止浮点累加。
- 账本采用 **仅追加事件 + 税务批次为唯一真相**：现金、持仓、可用数量都可由事件与批次重建。
- 复式记账：每笔成交同时写现金流水、批次、持仓变动；任何时点满足：

```
现金余额 + 冻结现金 + 持仓市值 = 账户净值
期初资金 + 累计已实现盈亏 + 累计浮动盈亏 − 累计费用 − 累计税费 + 累计分红 = 期末净值
可用股数 + 冻结股数 = 总股数
现金 ≥ 0；总股数 ≥ 0；可用股数 ≥ 0
```

- 所有写操作带幂等键；同一请求重复提交只产生一笔成交。
- 账本只追加，不物理删除；冲正用反向流水。
- `paper_cash_entries`、`paper_fills`、`paper_lot_closes`、`paper_order_events`、`paper_nav`、`paper_snapshots`、`paper_audit_log` 禁止 `UPDATE`/`DELETE`，用 SQLite 触发器 `RAISE(ABORT)` 强制。
- 提供 `paper-rebuild` 命令：从事件与批次重建现金、持仓、可用数量，并与物化表逐项比对；不一致即 `LEDGER_MISMATCH`。
- 每个交易日收盘后自动对账；对账失败触发 kill switch 并告警。

**约束与索引：**

- 所有金额/股数字段 `CHECK (>= 0)`；`qty > 0`；`price_cents > 0`。
- `paper_orders.status` 与 `paper_decision_cards.status` 用 `CHECK` 限定枚举。
- 索引：`paper_orders(account_id, target_trade_date, status)`、`paper_fills(account_id, trade_date)`、`paper_cash_entries(account_id, trade_date)`、`paper_tax_lots(account_id, code, open_date)`。
- 外键全部启用（`PRAGMA foreign_keys = ON`）；删除父行一律禁止，用状态关闭。
- 迁移使用事务；迁移前自动备份。

### 7.4 订单状态机

```
confirmed → settlement_pending → filled
                              ↘ rejected
                              ↘ expired
                              ↘ trigger_not_met
confirmed → canceled（仅 09:15 截止前）
```

| 状态 | 含义 | 允许的下一状态 |
|---|---|---|
| `confirmed` | 用户确认，已冻结资金/股数 | `settlement_pending` / `canceled` |
| `settlement_pending` | 09:15 截止后冻结，等待 16:20 结算 | `filled` / `rejected` / `expired` / `trigger_not_met` |
| `filled` | 已按官方开盘价成交 | 终态 |
| `rejected` | 风控/停牌/涨跌停/数据质量/风险缺口 | 终态 |
| `expired` | 缺价或未能在目标日结算 | 终态 |
| `trigger_not_met` | 开盘条件单未满足 | 终态 |
| `canceled` | 截止前用户撤销 | 终态 |

- 所有状态变更使用条件 SQL：`UPDATE paper_orders SET status = ? WHERE id = ? AND status = ?`；影响行数为 0 即并发冲突，拒绝并记录。
- 每次状态变更必须同时写 `paper_order_events`，`seq` 从 1 递增；事件与状态更新在同一事务。
- 09:15 后 `cancel` 返回 `TOO_LATE`，不静默失败。
- `execute` 幂等：相同 `client_request_id` 且请求体 hash 相同 → 返回同一订单；hash 不同 → 409 `IDEMPOTENCY_CONFLICT`。
- 成交写入以 `paper_fills.order_id UNIQUE` 兜底；重复结算插入失败即回滚，不重复记账。

**原因码（新手可读）：**

| 码 | 文案 |
|---|---|
| `RISK_POSITION_CAP` | 这只股票会超过单票上限 |
| `RISK_INDUSTRY_CAP` | 这个行业会超过行业上限 |
| `RISK_CASH` | 现金不够（含费用） |
| `RISK_DAILY_LOSS` | 今天亏损已达上限，暂停买入 |
| `RISK_DRAWDOWN` | 组合回撤触发暂停 |
| `RISK_T1` | 今天买的股票明天才能卖 |
| `RISK_GAP` | 按开盘价算，这笔会超过单笔最大亏损 |
| `LIMIT_UP` | 开盘涨停，买不到 |
| `LIMIT_DOWN` | 开盘跌停，卖不出 |
| `SUSPENDED` | 停牌，无法成交 |
| `MISSING_PRICE` | 缺少官方开盘价，今天不成交 |
| `DATA_QUALITY` | 数据质量不通过，暂停交易 |
| `TRIGGER_NOT_MET` | 开盘价没满足条件，委托作废 |
| `TOO_LATE` | 已过 09:15 确认截止时间 |
| `ODD_LOT` | 卖出零股必须一次卖完 |

## 8. 纸面撮合规则（A 股）

### 8.1 适用范围

- MVP 股票池：用户自选 ∪ 系统候选 ∪ 当前持仓，最多 50 只；仅限沪深主板、创业板、科创板中规则可编码的标的。
- 排除：ST/*ST、退市整理、上市不足 60 个交易日、停牌、ADV 不足、北交所（首期不纳入）。
- 仅做多；不支持融资融券、卖空、杠杆、ETF、可转债、期权。
- 每股最小买入单位：主板/创业板 100 股整数倍；科创板 200 股起、1 股递增。卖出可卖零股，但零股必须一次卖完。

### 8.2 委托类型（MVP 只有两种）

| 类型 | 行为 | 说明 |
|---|---|---|
| `open_market` | 以目标日官方开盘价 + 滑点成交 | 用于已触发卡的常规执行 |
| `open_price_condition` | 开盘价满足 `condition_op` 才成交，否则 `TRIGGER_NOT_MET` | 用于 `trigger_basis='open_auction'` |

**MVP 不支持：** 限价单、止损单、止盈单、盘中市价、任何依赖分钟线 high/low 的委托。需要限价/止损时，只能编码为开盘条件单，并明确告知“不是真实止损单”。

### 8.3 结算算法（16:20，按官方日线）

**通用前置检查：**

1. 目标交易日是交易日；账户未关闭；规则版本未漂移。
2. 官方日线已入库，且能取到 `open`、`limit_up`、`limit_down`、停牌状态；任一缺失 → `MISSING_PRICE`，不成交。
3. 停牌 → `SUSPENDED`。
4. 卡片状态仍为 `confirmed`，`card_version` 与委托一致；卡片未被证伪/忽略/降级。
5. 数据质量非 `fail`；账户不处于 kill switch（减仓除外）。

**买入：**

1. 若 `open >= limit_up` → `LIMIT_UP`，不成交。
2. 条件单：若 `open > trigger_price_cents` → `TRIGGER_NOT_MET`。
3. 成交价 = `open × (1 + slippage)`，向上取整到分；不得超过涨停价；条件单不得超过 `trigger_price_cents`。
4. 数量按最小单位向下取整；若不足一手 → `rejected(RISK_CASH)` 或卡阶段已降为观察。
5. 费用 = 佣金 + 过户费；买入不收印花税。
6. 现金扣减 = 成交金额 + 费用；若不足以覆盖冻结额 → `RISK_CASH`。
7. 按实际成交价重算最大亏损：`(成交价 − 止损价) × 股数 + 费用`；超过单笔上限 → `RISK_GAP`，不成交。

**卖出：**

1. 若 `open <= limit_down` → `LIMIT_DOWN`，不成交。
2. 条件单：若 `open < trigger_price_cents` → `TRIGGER_NOT_MET`。
3. 成交价 = `open × (1 − slippage)`，向下取整到分；不得低于跌停价；条件单不得低于 `trigger_price_cents`。
4. 只能卖 `available_shares`；零股必须一次卖完，否则 `ODD_LOT`。
5. 费用 = 佣金 + 印花税 + 过户费；按 FIFO 批次计算已实现盈亏与红利税。

**成交时点：** `trade_time` 记为 `09:25`（集合竞价时点），`settled_at` 为 16:20 实际结算时间，`price_basis='official_daily_open'`。UI 在结算前显示“已确认，待收盘确认”。

**同事务写入：** 成交、现金流水、批次、批次平仓、持仓物化、冻结释放、订单事件、卡片状态、审计日志必须在同一事务内完成；任一步失败全部回滚。

### 8.4 费用（默认，可配置）

| 费用 | 默认 | 方向 | 说明 |
|---|---|---|---|
| 佣金 | 成交额 × 0.025%，最低 ¥5 | 买/卖 | 可配置；不同券商不同 |
| 印花税 | 成交额 × 0.05% | 卖 | 按现行税率；政策变化时更新版本 |
| 过户费 | 成交额 × 0.001% | 买/卖 | 沪深统一口径，按最新规则 |
| 滑点 | 成交价 × 0.05% | 买/卖 | 买入加、卖出减；可用固定值或“1 个最小价位取大” |

- 所有费用按分取整，规则写入 `paper_policy_versions`。
- 费用假设必须保守；宁可高估成本，不低估。
- 每次费率变化新建版本，历史成交不重算。

### 8.5 T+1、冻结与可用数量

- 可用数量由批次派生：`open_date < trade_date` 的批次 `qty_remaining` 之和为可卖数量；当日买入批次不可卖。
- 用户确认时冻结：买入冻结现金（含费用缓冲）；卖出冻结股数。冻结写入 `paper_reservations`。
- 成交时同事务扣减并释放冻结；拒绝/撤销/过期时释放冻结。
- 不得用“修改 `available_shares`”代替冻结；所有冻结必须有对应 reservation 记录。
- 卖出所得现金当日可用于买入（A 股资金 T+0 可用）；模拟盘不涉及提现。

### 8.6 停牌、涨跌停、公司行动

- **停牌**：不撮合；已有委托 `rejected(SUSPENDED)` 或 `expired`；持仓按最近收盘价估值并标 `stale`。
- **涨跌停**：按板块/ST/新股规则取当日涨跌停价；不得统一按 10%。开盘触及涨停的买单不成交，开盘触及跌停的卖单不成交；不模拟排队。
- **分红**：股权登记日按批次记录受益（`paper_dividend_entitlements`）；派息日现金入账（税前）；卖出时按批次持有期代扣红利税（≤1 个月 20%，1 个月–1 年 10%，>1 年 0），税率写入政策版本。未实现批次或税率未知时，不得默认按 0 税率高估收益；至少按 10% 保守预扣并在复盘标注。
- **送转/拆股**：按比例调整各批次 `qty_opened` / `qty_remaining`，`cost_total_cents` 保持不变；零股向下取整，差额按除权参考价折现金补偿并写流水。
- **卖出成本**：按 FIFO 从最早未平批次扣减，`paper_lot_closes` 记录每笔已实现盈亏、持有天数、代扣红利税；胜率、盈亏比、利润因子均以此为准，不用移动平均成本倒推。
- **配股/增发/合并**：MVP 不自动处理；标记 `unhandled_corporate_action`，暂停该标的新委托，要求人工复核后记账。
- **退市**：标记 `delisted`；停止新委托；持仓按最后可得价格估值并标 `stale`，在复盘中要求人工确认减值，不伪造退出价。
- **持有后变 ST/停牌**：不再生成买入/加仓卡；只允许减仓或退出；若数据不可用，只能保留并标注，不得假装已卖出。

### 8.7 估值

- 持仓市值 = Σ(`qty_remaining` + 冻结股数) × 最新收盘价；缺价时不计入市值，列入 `missing_codes`，不得按 0 计算。
- 账户净值 = 现金 + 冻结现金 + 持仓市值。
- 当日收益 = 当日净值 / 前一日净值 - 1；无前一日净值时为空，不填 0。
- 基准：现金（0%）、全收益指数（如 H00300/H00905）、等权自选。每个基准单独展示，不混成一条“基准”。
- 若只能取得价格指数，必须叠加股息率并标注“估算全收益”，不得把约 2%/年的股息算成 alpha。
- 等权基准定义为“期初等权买入并持有、月度再平衡”，保存成分快照与再平衡记录。
- 复权：估值用未复权价 + 公司行动；绩效用复权净值。两套口径不得混用。

## 9. 风控引擎

### 9.1 原则

- 风控是硬约束，不是提示；不通过就不生成委托。
- 风控在**卡生成、用户确认（execute）、收盘结算（fill）**三处都检查；任一失败即拦截。
- 所有拦截可解释、可追溯、可复核；不允许“静默降级”。
- 参数锁定在 `paper_policy_versions`；修改需新版本并记录原因。
- 风控数据不足时倾向于“不交易”，但不得因单只股票缺价就误停整个账户。

### 9.2 MVP 规则

| 规则 | 默认阈值 | 动作 |
|---|---|---|
| 单票上限 | 净值 20% | 拦截加仓 |
| 行业上限 | 净值 40% | 拦截加仓 |
| 最大持仓数 | 5 只 | 拦截新开仓 |
| 单日新开仓 | 1 只 | 拦截 |
| 单日委托数 | 3 笔 | 拦截 |
| 现金缓冲 | 净值 5% | 拦截 |
| 单笔最大亏损 | 净值 2% | 卡阶段不出可执行卡；成交阶段超限按 `RISK_GAP` 拒绝 |
| 单日亏损 | 净值 2% | 当日禁止新买入；只停买入，不停估值/对账 |
| 组合回撤 | 峰值回撤 10% | kill switch：禁止新买入，要求人工复核 |
| 流动性 | 20 日 ADV ≥ ¥5,000 万；持仓 ≤ ADV 5% | 拦截 |
| 一手可行性 | 一手金额 ≤ 单票上限 | 超过则只给观察卡 |
| 停牌/ST/退市/新股 | 排除 | 拦截 |
| T+1 | 当日买入不可卖 | 拦截 |
| 数据质量 | `fail` | 全局禁止交易 |
| 对账 | 日终不平衡 | kill switch |

### 9.3 持仓风险扫描

- 每个交易日 16:20 对所有持仓生成观察/谨慎/退出卡，不依赖行业是否入选。
- 买入后持续监控证伪条件；证伪触发时生成退出卡，不等下一次行业筛选。
- 持有后变 ST、停牌、退市：只允许减仓/退出；买入路径直接拦截。
- 用户可手动发起“纸面减仓”，必须填写原因并标记 `off_plan`；执行后进入复盘，不计入“按计划执行”。
- 手动减仓仍需通过 T+1、跌停、停牌、数据质量检查；不提供“一键清仓”。

### 9.4 错误分级与账户状态

| 类型 | 触发 | 行为 | 是否停账户 |
|---|---|---|---|
| `MISSING_PRICE` | 缺某只标的官方价格/涨跌停/停牌状态 | 禁止该标的新买入；已有持仓标 `stale`；继续对账其他标的 | 否 |
| `DATA_QUALITY` | 关键数据全局不可用、规则版本不明 | 全局禁止新交易 | 是（交易层面） |
| `LEDGER_MISMATCH` | 对账恒等式不成立、重建不一致 | kill switch，禁止所有新委托（含减仓需人工复核） | 是 |
| `RISK_DRAWDOWN` | 回撤超限 | kill switch，禁止新买入；允许有数据的减仓 | 交易层面 |

### 9.5 Kill switch

- 触发条件：回撤超限、对账失败、数据质量 fail、连续 3 日无法估值、人工按下。
- 行为：停止所有新委托；已有持仓只允许减仓（如果数据可用）；页面顶部红色横幅（图标 + 文案，不只靠颜色）；通知任务中心。
- 解除：最早在**下一个交易日**，且必须由用户填写原因、完成一次复盘、系统验证数据恢复；解除记录进审计日志。
- 不得当日触发当日解除；不得自动解除。

### 9.6 风控事件

- 每条事件包含：规则、阈值、实际值、动作、相关订单/卡、时间、数据质量。
- 新手文案示例：“这笔买入会让白酒行业占到组合的 43%，超过 40% 上限，所以没有执行。”
- 事件不删除；误报也要保留并标注。

## 10. 复盘与评估

### 10.1 每日复盘

收盘后自动生成，包含：

1. 今日是否有操作；如果没有，为什么（无卡/未触发/风控/数据）。
2. 成交明细：买卖、官方开盘价、数量、费用、滑点、结算时间。
3. 净值变化、基准变化、超额。
4. 对账结果：四条恒等式、缺失价格、异常。
5. 风险事件与违规。
6. 持仓变化、集中度、证伪条件状态。
7. 明日待办：到期复核、触发条件、数据修复。

### 10.2 每周复盘

- 周收益、超额、最大回撤、波动、成交次数、换手、费用拖累。
- 系统判断：影子组合本周成交、净值、超额。
- 我的执行：实际组合本周成交、净值、超额。
- 执行率与偏离：计划执行率、漏执行、延迟执行、额外操作（`off_plan`）及原因。
- 数据质量：缺失、延迟、冲突、修复情况。
- 下周关注：候选池、行业变化、政策日历。
- 周复盘用事实陈述，不给“你做得很好/很糟”的评价；评价只针对可核对的行为。

### 10.3 双轨度量（影子 vs 实际）

每个实验同时维护两个账户：

| 账户 | 谁做决定 | 执行范围 | 目的 |
|---|---|---|---|
| 影子 `shadow-<experiment>` | 系统 | 所有触发卡按同一仓位自动执行 | 衡量方法本身 |
| 实际 `paper-<experiment>` | 用户 | 用户确认的委托 | 衡量用户纪律 |

**报告固定三栏：**

1. **系统判断（影子）**：触发卡数、成交数、净值、超额、回撤。
2. **我的实际执行（纸面）**：确认数、成交数、净值、超额、回撤。
3. **计划执行率与偏离原因**：执行率 = 实际成交卡 / 触发卡；偏离原因分 `not_confirmed`（看到但没确认）、`risk_blocked`（风控拦截）、`data_blocked`（数据缺失）、`off_plan`（计划外操作）、`manual_delay`（延迟执行）。

- 影子成交不产生用户委托，不影响实际账户现金/持仓；两条净值曲线不得混算。
- 影子账户同样受涨跌停、停牌、T+1、费用约束，不允许“理想成交”。
- 执行率低于 80% 时，报告优先解释偏离原因，不先谈收益。

### 10.4 决策结果评估

每张卡在 5/20/60 个交易日（按 `horizon`）评估；三个 cohort 分开统计：

| Cohort | 定义 | 用途 |
|---|---|---|
| 全部卡 | 所有生成的卡 | 系统覆盖面与噪声 |
| 触发卡 | 触发条件满足的卡 | 方法有效性主口径 |
| 执行卡 | 用户实际确认并成交的卡 | 用户纪律与执行偏差 |

| 字段 | 说明 |
|---|---|
| `return_pct` | 从触发价/决策价到评估日的复权收益 |
| `benchmark_return_pct` | 同期基准收益 |
| `alpha_pct` | 超额 |
| `max_adverse_pct` | 期间最大不利变动（MAE） |
| `hit` | 是否跑赢基准（主口径）；另记是否盈利 |
| `reason_class` | `right_reason` / `right_luck` / `wrong_reason` / `wrong_luck` / `not_triggered` |
| `invalidation_hit` | 是否触发证伪条件 |
| `notes` | LLM 归纳 + 用户备注 |

**“对错”不只看盈亏：**

- 判断对、执行对、赚钱 → 可复制。
- 判断对、执行错、赚钱 → 运气，不可复制。
- 判断错、执行对、亏小钱 → 可接受，记录教训。
- 判断错、执行错、亏大钱 → 红线，必须复盘。

### 10.5 有效性指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 累计收益 | 期末净值 / 期初净值 - 1 | 总览 |
| 年化收益 | 按 252 日折算；不足 1 年标注“未年化” | 对比 |
| 超额收益 | 组合收益 - 全收益基准收益 | 核心 |
| 最大回撤 | 日净值峰谷最大跌幅 | 风险 |
| 夏普 | (日均收益 − 无风险利率) / 日收益标准差 × √252；默认无风险利率 0，标注 | 风险调整 |
| 索提诺 | 只用下行波动 | 下行风险 |
| 胜率 | 盈利平仓交易 / 总平仓交易 | 交易层面 |
| 决策命中率 | 跑赢基准的到期触发卡 / 到期触发卡 | 决策层面 |
| 盈亏比 | 平均盈利 / 平均亏损 | 交易层面 |
| 利润因子 | 总盈利 / 总亏损 | 交易层面 |
| 换手率 | 买卖金额 / 平均净值，年化 | 成本 |
| 费用拖累 | 佣金+印花税+过户费+滑点 / 平均净值，年化 | 成本 |
| 集中度 | 前三大持仓权重、HHI | 风险 |
| 执行率 | 实际成交卡 / 触发卡 | 纪律 |
| Brier 分数 | 用 `p_outperform` 与实际二值结果求平均平方误差；仅在 `calibration_status='calibrated'` 且 ≥250 天/100 张触发卡时计算 | 校准 |
| 状态分组 | 按牛/熊/震荡、行业、市值、波动分组 | 稳健性 |
| 压力测试 | 历史极端区间回放、成本翻倍、滑点翻倍、延迟一天成交 | 韧性 |

**统计纪律：**

- 少于 120 个有效交易日、最后一张卡不满 60 日、或触发卡少于 30 张：只显示计数与描述，**不显示百分比结论**，不宣称“有效”。
- 少于 250 个有效交易日或 100 张触发卡：不做显著性结论；可给 bootstrap 置信区间，但必须标注样本不足。
- `p_outperform` 未校准前，只作为内部记录，不展示给用户，不进入阶段门；不得用展示用的 `confidence` 顶替概率。
- 不挑时间段、不删亏损样本、不按结果调参数；所有版本保留。
- 评估窗口开始前锁定基准、指标、阈值；开始后修改视为新实验。

### 10.6 实验与重置

- 每个实验锁定：协议、规则版本、初始资金、基准、阈值、计划有效天数。
- 暂停原因必须记录；暂停日不计入有效交易日。
- 重置 = 旧账户关闭只读 + 新开 `-v2` + 重新计时 + 显示重置次数；旧结果保留。
- 没有新实验记录，不得重置；不得用“清空数据”冒充新实验。
- 规则变更、费用变更、基准变更都触发新实验版本；不得在同一个实验里悄悄改参数。

### 10.7 阶段门评分

**L1 → L2（过程与完整性门，二值否决 + 加权）：**

| 维度 | 分值 | 通过要求 |
|---|---|---|
| 数据与运维 | 25 | 数据可用率 ≥ 99%；对账 100% 平衡；无前视审计失败；重大事故 ≤ 1 次且已修复 |
| 决策过程 | 20 | 卡片字段完整率 100%；规则版本未漂移；每张卡有反证；证据可追溯 |
| 执行链路 | 20 | 无重复成交；无未对账差异；每笔成交可按官方价解释；崩溃重放通过 |
| 行为 | 15 | 无超仓；无绕过风控；kill switch 解除合规 |
| 用户体验 | 10 | 可用性验收通过；新手能分清“系统判断/我的执行” |
| 合规 | 10 | 免责声明、数据许可、审计日志齐全；无真实委托能力 |

**L2 → L3（绩效与校准门）：**

| 维度 | 分值 | 通过要求 |
|---|---|---|
| 绩效 | 30 | 扣费后超额 > 0；最大回撤 ≤ 10%；夏普 > 0.5（≥250 天/100 张触发卡） |
| 校准 | 15 | `calibration_status='calibrated'`；Brier 优于基准基线 |
| 过程 | 25 | 同 L1→L2 的数据、决策、执行项 |
| 行为 | 15 | 按计划执行率 ≥ 90%；无未经复核的 kill switch 解除 |
| 合规 | 15 | 同 L1→L2 的合规项 |

**门槛：**

- 前视审计失败、对账不平衡、合规缺项是**二值否决**，任何一项不通过即不进入下一级。
- 加权总分 ≥ 80，且每个单项得分率 ≥ 60%。
- 绩效维度样本不足时，该项记 0 并延长观察，不按“观察”给分。
- 门槛在实验开始前写入 `paper_policy_versions`，不得中途下调。

## 11. 技术架构

### 11.1 模块边界

```
数据接入层
  ├─ source adapters（Tushare / 交易所 / 巨潮 / 新闻 / 延迟报价）
  ├─ 数据质量检查
  ├─ 标的元数据与股票池
  └─ PIT 快照构建
        ↓
决策层
  ├─ 市场状态
  ├─ 行业筛选
  ├─ 个股筛选
  ├─ 持仓风险扫描
  ├─ 决策卡生成（确定性规则）
  └─ LLM 叙述（只读结构化证据，异步）
        ↓
风控层
  ├─ 卡级风控
  ├─ 确认级风控
  └─ 结算级风控
        ↓
执行层
  ├─ ExecutionGateway（接口）
  │    ├─ PaperGateway（本期）
  │    ├─ BrokerSandboxGateway（未来）
  │    └─ LiveGateway（更远）
  ├─ 纸面结算（官方开盘价）
  ├─ 影子组合
  └─ 账本（仅追加事件 + 税务批次）
        ↓
复盘层
  ├─ 每日对账（四条恒等式）
  ├─ 每日/每周复盘
  ├─ 决策结果评估（三 cohort）
  └─ 指标与实验报告
```

### 11.2 `ExecutionGateway` 接口（本期只实现 Paper）

```ts
interface ExecutionGateway {
  submit(order: PaperOrderInput): Promise<ExecutionResult>
  cancel(orderId: string): Promise<ExecutionResult>
  getOrder(orderId: string): Promise<OrderSnapshot>
  getFills(orderId: string): Promise<FillSnapshot[]>
  reconcile(date: string): Promise<ReconcileReport>
}
```

- 本期只有 `PaperGateway`；不得在代码中直接调用任何券商 SDK。
- 未来 `BrokerSandboxGateway` / `LiveGateway` 必须复用同一接口和同一风控前置。
- `LiveGateway` 在 L3 之前不实现、不配置、不暴露 UI。

### 11.3 部署拓扑（L1 参考）

- **一台常开的自托管机器 + 单个 Node 进程 + 本地 SQLite**；systemd（Linux）或 launchd（macOS）守护，进程崩溃自动重启。
- Electron 与 PWA 作为**客户端**；不在客户端里跑调度。PWA 无服务端调度能力，不得假装能在后台生成卡片。
- 外部 dead-man 告警：每日 16:40 前未收到“结算完成”心跳，发送提醒（邮件/推送/本地通知）。
- 备份与主库同机不同目录；可选外部磁盘，不上传云。
- 本地数据优先；除 LLM API 与行情源外，不依赖云服务。
- L1 观察期内**不允许**把调度器跑在会休眠的笔记本上；若必须，需在数据健康页显示“休眠风险”。

### 11.4 调度与任务

复用现有单 worker 任务队列；新增任务类型：

- `paper_preopen_check`（08:30）
- `paper_cutoff`（09:15）
- `paper_data_ingest`（16:10）
- `paper_settle`（16:20）
- `paper_position_scan`（16:20）
- `paper_reconcile`（16:30）
- `paper_review_daily`（17:00）
- `paper_cards_next_day`（17:30）
- `paper_review_weekly`（周六 10:00）
- `paper_evaluate_outcomes`（17:15，评估到期卡）

**任务约束：**

- 所有任务幂等；重跑不重复成交、不重复记账。
- 单任务超时：数据类 10 分钟，对账类 5 分钟，LLM 叙述 2 分钟；超时标记失败并释放租约，不无限挂起。
- 租约重试不得重复结算：成交写入以 `paper_fills.order_id UNIQUE` 兜底，事务内完成。
- 交易日历守卫：非交易日直接跳过，不生成空报告。
- 追赶器只补行情入库、估值、对账、复盘；绝不补造 09:15 后卡片或成交（见 §4.4）。
- Web 无常驻调度时，页面明确提示“自动任务未运行”，并提供手动触发；不得假装已运行。

**安全：**

- 所有 `/api/paper/*` 写接口校验 Origin/Referer + 登录 + CSRF；仅桌面端校验 Origin 不够。
- 会话 cookie 保持 `HttpOnly` + `Secure`；评估 `SameSite=Strict` 或双提交 CSRF token。
- 幂等语义：相同 `client_request_id` + 相同请求体 hash → 200 返回同一订单；hash 不同 → 409 `IDEMPOTENCY_CONFLICT`。
- 金额、股数、价格、卡版本服务端重新校验；不信任前端。
- 审计日志记录操作者、前后值、时间、`request_hash`、`task_id`、`card_id`、`order_id`，并用 hash 链串联；不记录密钥。
- 不提供任何真实券商凭证字段；设置页不出现“接入券商”入口。
- 纸面数据不进入 `agent_share`；匿名分享页不得引用纸面持仓、委托、成交、净值。

### 11.6 存储、迁移与备份

- 连接初始化显式设置：`PRAGMA journal_mode = WAL`、`PRAGMA busy_timeout = 5000`、`PRAGMA foreign_keys = ON`。
- 现有进程内串行化保留，但不能替代数据库约束；约束必须在 schema 层。
- 迁移包事务；迁移前自动备份；失败回滚到备份。
- 每日收盘后 `VACUUM INTO` 或 `.backup` 生成快照，执行 `PRAGMA integrity_check` 并记录校验和；保留 30 天。
- 每月做一次恢复演练：从备份恢复到临时目录，跑 `paper-rebuild` 与对账，结果记录在数据健康页。
- 备份默认排除/脱敏密钥；备份文件权限 0600。
- Service Worker 对 `/api/paper/*` 加 denylist：不缓存纸面接口；离线态只读，禁止提交委托。

## 14. 验收标准

### 14.1 功能验收

- [ ] 新建纸面账户，初始资金 ¥200,000，现金流水平衡。
- [ ] 生成一张决策卡，包含 ≥3 条证据、≥1 条反证、触发、证伪、数字止损、仓位、复核日、快照 ID、`card_version`。
- [ ] 用户确认后生成委托；未确认不成交；09:15 后确认返回 `TOO_LATE`。
- [ ] 09:15 前确认的委托冻结现金/股数；撤销/拒绝后冻结释放。
- [ ] 收盘前 UI 显示“已确认，待收盘确认”，不显示“已成交”。
- [ ] 16:20 用官方开盘价结算；成交价、费用、滑点、结算时间、价格来源可解释。
- [ ] 买入当日不可卖；次日可卖；可用数量由批次派生。
- [ ] 开盘涨停买单不成交；开盘跌停卖单不成交；停牌不成交。
- [ ] 缺官方开盘价不成交，转 `MISSING_PRICE`，不顺延猜测，不用盘中价替代。
- [ ] 开盘条件单未满足时 `TRIGGER_NOT_MET`，不生成“稍后提醒再确认”。
- [ ] 实际成交价导致最大亏损超单笔上限时 `RISK_GAP`，不成交。
- [ ] 分红/送转后账本平衡；红利税在卖出时按批次持有期代扣；未处理公司行动被标记并暂停该标的。
- [ ] 日终对账四条恒等式全部成立；不平衡触发 kill switch。
- [ ] 风控拦截有具体规则、实际值、新手文案。
- [ ] 净值、全收益基准、超额、回撤、费用拖累、执行率可查看。
- [ ] 决策卡到期后生成结果评估；未到期不伪造结果；样本不足只显示计数。
- [ ] 影子组合与实际组合分账、分曲线、分指标；三栏报告可核对。
- [ ] 实验开始/暂停/重置有记录；重置后旧账户只读、新账户 `-v2`、计时重开。
- [ ] 持仓风险扫描覆盖所有持仓；持有后变 ST/停牌只允许减仓。
- [ ] 示例数据与真实数据不混用；示例水印可见。
- [ ] 非交易日显示“休市”，不生成空报告。

### 14.2 数据与审计验收

- [ ] 每张卡绑定不可变快照；快照保存决策实际使用的 OHLCV、复权因子版本、涨跌停价、停牌、行业、股票池。
- [ ] 注入未来公告/K 线/涨跌停价，决策与评估不变（前视审计通过）。
- [ ] 重复提交同一委托只产生一笔成交（幂等）；相同 key 不同 payload 返回 409。
- [ ] 所有写操作有审计日志；日志 hash 链可校验；不含密钥。
- [ ] 数据源失败时显示降级原因，不用旧数据冒充今日数据。
- [ ] 模拟盘无任何券商 SDK/真实下单代码路径。
- [ ] `adj_factor` 无硬编码；不同来源行情分行；历史行情修正有 hash 记录。
- [ ] 缺失涨跌停价/停牌状态/标的元数据时 `DATA_QUALITY fail`，不默认 10%。

### 14.3 账本与可靠性验收

- [ ] 账本属性测试：随机生成买卖、分红、送转、费用事件后，四条恒等式成立，无负现金、无负可用股数。
- [ ] 崩溃测试：成交事务提交后杀进程，重启重放不重复成交、不重复记账。
- [ ] 并发测试：同一订单并发 `execute`/`cancel`，只有一个状态转移成功。
- [ ] `paper-rebuild` 从事件与批次重建的现金/持仓/可用数量与物化表完全一致。
- [ ] 每日备份生成成功；`PRAGMA integrity_check` 通过；恢复演练可从备份启动并完成对账。
- [ ] 任务超时后释放租约；重试不重复结算。
- [ ] 服务 Worker 不缓存 `/api/paper/*`；离线态不能提交委托。

### 14.4 新手可用性验收

- [ ] 新用户 30 秒内能说出“今天要不要动、为什么”。
- [ ] 一张卡的首屏能回答：买什么、为什么、买多少、最多亏多少、何时复核。
- [ ] 不展开抽屉也能看到风险与反证；展开后能看到证据与快照。
- [ ] 任何拦截/失败都有“下一步怎么办”，不是只报错。
- [ ] 移动端单手可完成“看卡 → 确认 → 查看结果”。
- [ ] 术语有内联解释；不出现“夏普/索提诺/Brier”等词而不解释。
- [ ] 用户能分清“系统判断（影子）/我的执行”；执行率与偏离原因可见。
- [ ] 第一次亏损时看到的是事实、原因和下一步，不是鼓励或责备。

### 14.5 性能与部署验收

- [ ] 决策卡生成 ≤ 60 秒（50 只股票池，缓存命中时 ≤ 15 秒）；LLM 叙述不阻塞。
- [ ] 结算 ≤ 10 秒完成全部委托（50 只以内）。
- [ ] 日终对账 ≤ 30 秒。
- [ ] 页面首屏（模拟盘总览）≤ 2.5 秒（本地/局域网）。
- [ ] 单 Node 进程 + 本地 SQLite 在目标机器连续运行 7 天，无内存泄漏、无任务堆积。
- [ ] 模拟一次进程崩溃、一次断网、一次数据源超时：重跑后账本平衡，页面显示降级原因。
- [ ] dead-man 心跳在结算未完成时能触发告警。

### 15.1 主要风险

## 18. 研发对齐结论（技术决策）

以下五项在第二轮评审中定稿；实现不得自行更改，需变更时走新实验版本。

### 决策 1：成交定价时点

**决定：** 09:15 截止并冻结；16:10 官方日线入库；16:20 用官方开盘价结算。

**理由：** Tushare 日线 16:00 后才稳定；09:25 实时撮合无法同时满足“权威数据”和“开盘价成交”。盘中延迟报价只用于风险提示，不用于成交。

**放弃的方案：** 09:25 用盘中报价成交（数据不可信）；次日用前收盘价成交（不是真实可执行价）；收盘价成交（与“开盘执行”语义不符）。

### 决策 2：确认与触发

**决定：** 每笔委托必须显式 `execute`；服务端在 execute 与 fill 两处重查卡状态、数据质量、策略哈希、风控；`card_version` 不匹配返回 409；`open_auction` 只能编码为开盘条件单。

**理由：** 自动转委托与“用户确认”冲突；09:15 前无法判定开盘价；触发后提醒再确认在开盘价模型下不可实现。

**放弃的方案：** 09:15 自动把触发卡转委托；盘中触发后推送再确认；用 LLM 判断是否“触发”。

### 决策 3：账本真相源

**决定：** 仅追加事件 + 税务批次为唯一真相；现金/持仓/可用数量可重建；确认时冻结；唯一键/CHECK/防更新触发器；`paper-rebuild`；审计 hash 链。

**理由：** 纯物化表无法证明历史，崩溃与并发下容易重复成交；批次是红利税、T+1、已实现盈亏的共同基础。

**放弃的方案：** 只存现金余额与持仓快照；用移动平均成本倒推已实现盈亏；用应用层串行化代替数据库约束。

### 决策 4：PIT 与元数据

**决定：** 不可变 `paper_snapshots` 保存决策实际使用的精确事实；成交记录 `price_source_id`、`bar_fetched_at`、`bar_hash`；SCD2 `symbol_meta`；未知字段直接 `DATA_QUALITY fail`。

**理由：** `fact_snapshots` 只存引用，底层表可变；`adj_factor=1` 和默认 10% 涨跌停会让历史结果失真。

**待 spike：** Tushare 积分/限频是否覆盖每日全量；免费源能否稳定提供涨跌停价、停复牌、分红；未来 370 天日历是否可得。

### 决策 5：无人值守拓扑

**决定：** 自托管单 Node 进程 + 本地 SQLite + systemd/launchd + 外部 dead-man；Electron/PWA 仅作客户端；M0 后先做 7 天异常演练。

**理由：** PWA 无服务端调度；Electron 默认 30 分钟、Windows 关窗退出；现有任务无超时、`MAX_ATTEMPTS=2`，不足以支撑 3–6 个月观察。

**放弃的方案：** 依赖 Electron 常驻；依赖 PWA 后台；在 Vercel 等无状态环境跑调度。

### 待 spike 清单（按顺序）

1. 数据源可用性：Tushare 积分、限频、涨跌停、停复牌、分红、复权、日历；免费源替代。
2. 撮合回填：官方开盘价 + 涨跌停 + 停牌 + 条件单的边界夹具。
3. PIT/账本回放：快照不可变、事件重建、崩溃重放、并发状态转移。
4. 无人值守演练：7 天连续运行、断网、数据源超时、进程崩溃、dead-man。
5. UI 可用性测试：新手能否分清“待收盘确认”、看懂风险信封、找到执行入口。

### 开放问题

- 全收益指数（H00300/H00905）的免费稳定来源与许可。
- 等权自选的月度再平衡成本是否计入基准（建议计入，保持可比）。
- 新股上市前 5 日无涨跌停的规则版本如何编码。
- 科创板 200 股起、1 股递增在卖出零股时的边界。
- 港股通/北交所未来纳入时的规则扩展点。
