## 0. 一句话定义

用**真实 A 股数据**、**虚拟资金**、**纸面成交**，每天生成可追溯的决策卡，按固定规则模拟买卖并逐日对账，用 3–6 个月的前向结果检验这套投研方法是否值得继续投入——全程不接券商、不碰真钱、不构成投资建议。

---

## 1. 为什么做、做到什么程度

### 1.1 要解决的问题

当前产品已经能看收盘简报、行业判断、自选、持仓、论点和任务，但用户仍无法回答三个关键问题：

1. 这些判断如果当时真的执行，结果会怎样？
2. 亏损是因为判断错了，还是因为买贵了、卖晚了、仓位重了？
3. 这套方法连续运行几个月后，是否比“什么都不做”更好？

模拟盘不是增加一个“炒股功能”，而是给现有研究加一条**可验证的闭环**：判断 → 决策卡 → 纸面委托 → 成交 → 持仓 → 复盘 → 评估。

### 1.2 产品边界（本期）

**做：**

- 真实行情、真实公告、真实交易日历；虚拟现金与虚拟持仓。
- 收盘后生成决策卡；次日开盘按规则纸面成交。
- 纸面账户、委托、成交、持仓、现金流水、每日净值。
- 风控检查、每日对账、每日/每周复盘。
- 与现金、沪深 300、中证 500、等权自选对比的有效性指标。
- 所有判断可追溯到数据快照、证据、规则版本。

**不做：**

- 不接券商、不发送真实委托、不管理真实资金。
- 不做盘中高频、不做分钟级自动交易、不做 T+0。
- 不做融资融券、不做卖空、不做杠杆、不做期权期货。
- 不让 LLM 直接决定买什么、买多少；LLM 只做证据归纳和情景解释。
- 不承诺收益，不输出“必涨/必跌”，不把模拟结果包装成实盘业绩。
- 不做公开荐股、组合跟单、社区排行。

### 1.3 与现有产品定位的衔接

现有定位是“政策-行业影响分析引擎”，强调研究、信息准备、证据可追溯。模拟盘是它的**验证层**，不是另一套荐股产品：

- 决策卡必须能回到“政策/行业/公司事件 → 价格与流动性确认 → 风险与反证”的证据链。
- 决策卡的结论是“研究性操作提案”，不是投资建议。
- 模拟盘页面固定展示“虚拟资金，不是真实持仓；不构成投资建议”。

### 1.4 成功标准

MVP 的成功不是“赚了多少钱”，而是：

1. **过程可信**：每一笔纸面成交都能解释清楚——哪张卡、什么证据、什么规则、什么价格、什么费用。
2. **数据可信**：不使用未来数据，不混用示例数据，缺数据时显式降级而不是猜。
3. **账本可信**：每日对账平衡，现金、持仓、净值、基准能对上。
4. **用户能懂**：新手能在 30 秒内看懂“现在该不该动、为什么、最坏亏多少”。
5. **可评估**：120 个交易日后，能给出扣费后的超额、回撤、命中率、校准度，而不是只给一条净值曲线。

## 2. 用户与核心场景

### 2.1 用户

- 主要用户：有 A 股账户、但缺少系统研究流程的个人投资者；能看懂涨跌和市盈率，不熟悉机构术语。
- 使用方式：每天盘前 5 分钟、盘后 10 分钟；周末 20 分钟复盘。
- 设备：手机优先，桌面增强；本地数据优先，不依赖云服务。

### 2.2 核心任务（JTBD）

| 场景 | 用户想完成的事 | 模拟盘要给出的答案 |
|---|---|---|
| 盘前 | 今天要不要动？ | 今天没有/有几张决策卡；每张卡的建议动作、触发条件、最大仓位、最大亏损 |
| 盘中 | 有没有需要处理的？ | 只提示风险与触发，不诱导频繁交易；默认“不操作” |
| 盘后 | 今天做对了没有？ | 成交回报、净值变化、与基准对比、是否违反计划 |
| 周末 | 这套方法靠谱吗？ | 周度复盘、决策质量、数据质量、下周关注 |
| 任意时刻 | 为什么买/为什么没买？ | 决策卡 + 证据 + 快照 + 规则版本 |

### 2.3 新手行为约束

- 默认不操作；没有明确触发条件就不生成委托。
- 一笔委托必须展示：买什么、为什么、买多少、最多亏多少、费用多少、什么时候复核。
- 不允许“一键全仓”“一键跟单”“自动加仓”。
- 术语第一次出现时给一句人话解释；详细解释放抽屉，不打断主任务。
- 任何“系统建议”旁边必须有置信度和反证，不能只给结论。

## 3. 验证阶梯与阶段门

模拟盘只是第二级，不允许跳级。

| 级别 | 内容 | 时长/样本 | 通过后才能进入 |
|---|---|---|---|
| L0 历史回测 | 用历史数据回放规则，检查是否存在明显前视、幸存者偏差、成本遗漏 | 至少 5 年；含 2015/2018/2022 等压力区间 | L1 |
| L1 前向纸面 | 真实数据、虚拟资金、每日运行，不允许改规则 | 3–6 个月或 ≥120 个交易日 | L2 |
| L2 券商沙盒 | 券商模拟环境，验证委托、成交、撤单、对账接口 | 1–3 个月 | L3 |
| L3 小资金实盘 | 极小资金，人工确认每笔，严格风控 | 3–6 个月 | L4 |
| L4 全自动 | 分析、决策、执行、复盘全自动，保留总开关 | 持续 | — |

**阶段门规则：**

- 每一级开始前锁定规则版本、资金规模、评估窗口、通过阈值；开始后不许移动球门。
- 任何规则、参数、费用假设的修改都产生新版本，并重新计时；旧版本结果保留，不覆盖。
- L1 的主要通过条件是“过程与账本可信”，不是“必须赚钱”；收益指标用于观察，不单独作为进入 L2 的依据。
- L1 出现以下任一情况直接不通过：前视数据、账本对不上、示例数据混入、风控被绕过、无法解释的成交。

## 4. 每日运行闭环

### 4.1 时间表（Asia/Shanghai，交易日）

| 时间 | 任务 | 产出 | 失败时 |
|---|---|---|---|
| 08:30 | 盘前快照 | 隔夜外盘、公告、新闻、前一交易日行情、今日日历 | 标记降级；缺关键数据则不生成新卡 |
| 08:45 | 决策卡生成 | 0–5 张卡；每张含证据、触发、证伪、仓位、复核日 | 任务失败可见；不补造卡片 |
| 09:15 | 委托截止 | 将“今日执行”的卡转为纸面委托 | 过期卡自动作废并说明 |
| 09:25 | 开盘集合竞价 | 按开盘价与规则撮合 | 缺开盘价则拒绝，不顺延猜测 |
| 09:30–11:30 / 13:00–15:00 | 盘中监测 | 风险事件、触发条件、数据延迟提示 | 只提示，不自动加仓 |
| 15:05 | 收盘数据入库 | 日线、涨跌停、成交额、停复牌 | 缺数据则当日估值标记为 stale |
| 16:10 | 每日对账与复盘 | 账本平衡、净值、基准、违规、明日计划 | 对账失败触发 kill switch |
| 17:00 | 决策结果评估 | 到期卡的 5/20/60 日结果 | 缺价格则延期，不填 0 |
| 周六 10:00 | 周度复盘 | 周收益、超额、回撤、决策质量、数据质量 | 生成失败可在任务中心重跑 |

**休市日：** 不生成卡、不撮合、不估值；页面显示“今日休市”，而不是空白或昨日数据。

### 4.2 决策节奏（MVP 只做两种）

1. **盘后决策，次日开盘执行**：T 日收盘后生成卡，T+1 日 09:25 按开盘价纸面成交。
2. **盘前决策，当日开盘执行**：T 日 08:45 前生成卡，T 日 09:25 成交。

**不做盘中决策。** 盘中只做风险监测和触发提示；用户若手动记录“盘中想法”，只能进日志，不能直接生成委托。

### 4.3 默认动作

- 没有满足条件的标的：明确显示“今天不操作”，并给出原因（市场状态、数据质量、风险预算）。
- 有卡但未触发：显示“等待触发”，不提前下单。
- 触发但风控不通过：显示“被风控拦截”，给出具体规则和申诉/复核入口。
- 用户不确认：不成交。MVP 每笔纸面委托都需要用户明确确认。

## 5. 数据架构

### 5.1 三层数据，各司其职

| 层 | 内容 | 用途 | 能否触发成交 |
|---|---|---|---|
| 权威事实层 | 交易所公告、巨潮公告、证监会政策、Tushare 日线/日历/复权因子/分红送转、交易所涨跌停价 | 决策、撮合、估值、对账 | 是（仅收盘后已发布数据） |
| 盘中监测层 | 新浪/腾讯/东财等延迟行情、涨跌停统计、成交额 | 盘中提示、风险告警 | **否**（MVP 不用于成交） |
| 研究叙述层 | 新闻、LLM 归纳、行业分析、情景解释 | 证据补充、人话解释 | **否**（不能单独成为买入理由） |

**关键原则：**

- 决策和成交只认权威事实层；盘中报价必须标注来源、时间、延迟秒数。
- 新闻只能作为证据之一，不能单独触发交易。
- 任何一层缺失，都要在卡片和页面显式标注，不允许用另一层“补一个看起来合理的数”。

### 5.2 MVP 数据源清单

| 数据 | 首选来源 | 层级 | 频率 | 备注 |
|---|---|---|---|---|
| 交易日历 | Tushare `trade_cal` | T1 | 每日 | 必须覆盖未来一年 |
| A 股日线（未复权） | Tushare `daily` | T1 | 每日收盘后 | 撮合与估值用未复权价 |
| 复权因子 | Tushare `adj_factor` | T1 | 每日 | 绩效与回测用复权价 |
| 每日指标（换手、量比、市值） | Tushare `daily_basic` | T1 | 每日 | 流动性过滤 |
| 涨跌停价 | 交易所公开数据 / Tushare `stk_limit` | T0/T1 | 每日 | 必须按板块与 ST 状态取，不能统一按 10% |
| 停复牌 | Tushare `suspend_d` / 交易所公告 | T1/T0 | 每日 | 停牌不成交 |
| 分红送转 | Tushare `dividend` / 交易所公告 | T1/T0 | 事件驱动 | 除权除息日必须处理 |
| 公告 | 上交所、深交所、巨潮 | T0 | 事件驱动 | 保存标题、链接、发布时间、原文 |
| 政策 | 证监会、央行、统计局、发改委 | T0 | 事件驱动 | 保存原文链接与发布时间 |
| 新闻 | 财联社、新浪 7×24、华尔街见闻 | 研究层 | 事件驱动 | 只作证据，不作成交依据 |
| 盘中延迟报价 | 新浪/腾讯 | 监测层 | 5–60 秒轮询 | 标注延迟；MVP 不用于成交 |
| 隔夜外盘 | CBOE 延迟 | 研究层 | 每日 | 只作背景 |

**数据许可与合规：**

- 免费源不等于可自由再分发；本项目只做个人本地研究，不对外提供数据 API、不转售、不公开展示原始行情。
- 每个源在 `source_registry` 记录 `terms_url`、启用状态、最近成功时间、连续失败次数。
- 被封 IP、限流、条款变化时，宁可停用并显示降级，不绕过限制。

### 5.3 快照与 PIT（Point-in-Time）

每张决策卡必须绑定一个不可变快照：

```
snapshot_id
as_of                 决策时点（含时区）
trade_date            决策针对的交易日
universe              本次扫描的股票池
dataset_version       数据集版本号
source_manifest_json  每个数据源的版本/时间/状态
quality_json          完整性、时效、一致性、来源质量
content_hash          内容哈希，防篡改
```

**PIT 规则：**

- 只用 `published_at <= as_of` 的公告和新闻；`effective_at` 晚于决策时点的政策不得提前使用。
- 行情只用截至上一收盘已发布的数据；不得使用当日收盘价做当日开盘决策。
- 财务数据用公告日，不用报告期；未公告的财报不得进入快照。
- 股票池使用决策时点的成分，不得用今天的指数成分回填历史。
- 退市股保留在历史库中；不得为了“回测好看”删除退市样本。
- 每张卡保存 `snapshot_id`；快照生成后不可修改，只能新建版本。

**前视审计：**

- 自动测试：注入一条 `published_at` 晚于 `as_of` 的公告，决策结果不得变化。
- 自动测试：注入一条未来K线，回测/评估结果不得变化。
- 每次规则变更后重跑审计；审计失败阻止发布决策卡。

### 5.4 数据质量门

| 状态 | 含义 | 对决策/成交的影响 |
|---|---|---|
| `pass` | 关键数据齐全、时效达标、来源一致 | 正常 |
| `warn` | 非关键数据缺失或轻微延迟 | 可生成卡，但卡上必须显示警告；用户确认后才能下单 |
| `fail` | 关键数据缺失、过期、冲突、示例数据混入 | **禁止生成新卡、禁止成交**；页面显示原因与修复入口 |

**关键数据（fail 级）：** 交易日历、目标股当日/前日行情、涨跌停价、停牌状态、账户现金、规则版本。
**非关键数据（warn 级）：** 新闻、外盘、行业分类、部分公告。

**时效阈值（可配置，默认）：**

- 日线：交易日 15:30 前必须入库；否则当日估值 `stale`。
- 公告：决策时点前 30 分钟内发布的公告必须已抓取；否则 `warn`。
- 盘中报价：超过 120 秒未更新，标 `stale`，不得用于任何触发判断。

### 5.5 示例数据隔离

- 延续现有 `assertNoDemoData`：一旦库中存在示例数据，禁止接入真实行情；模拟盘也不得在示例库上运行。
- 模拟盘账户、订单、成交、净值必须带 `is_demo` 标志；UI 固定显示“示例数据”水印。
- 测试夹具与生产数据分库；不得用“清空表”方式混用。

## 6. 决策卡

### 6.1 定义

决策卡是“一份可执行、可证伪、可复盘的研究结论”。它不是新闻摘要，也不是 LLM 的自由文本。

**一张卡只回答五个问题：**

1. 看什么？（标的、周期）
2. 现在是什么立场？（观察/候选/谨慎/回避）
3. 为什么？（支持证据 + 反证）
4. 什么条件下动手？（触发）
5. 什么条件下认错？（证伪）以及最多买多少、最多亏多少、什么时候复核。

### 6.2 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 稳定 ID |
| `trade_date` | date | 是 | 针对的交易日 |
| `as_of` | datetime | 是 | 决策时点（Asia/Shanghai） |
| `snapshot_id` | int | 是 | 绑定的不可变快照 |
| `code` / `name` | string | 是 | 标的 |
| `horizon` | enum | 是 | `short`（5–20 日）/ `swing`（20–60 日）/ `medium`（60–120 日） |
| `stance` | enum | 是 | `observe`（观察）/ `candidate`（候选）/ `caution`（谨慎）/ `avoid`（回避） |
| `intent` | enum | 否 | `none` / `buy` / `add` / `reduce` / `exit`；只有 `candidate` 可 `buy/add`，`caution/avoid` 可 `reduce/exit` |
| `thesis` | string | 是 | 一句话结论，≤80 字，必须包含“因为…所以…” |
| `evidence` | array | 是 | ≥3 条；至少 1 条政策/行业、1 条价格/量能、1 条风险/反证 |
| `trigger` | object | 是 | 触发条件；含价格/事件/时间窗口，必须可机器判定 |
| `invalidation` | object | 是 | 证伪条件；触发后卡状态转 `invalidated` |
| `max_position_pct` | number | 是 | 单票最大仓位，占组合净值比例 |
| `max_loss_pct` | number | 是 | 按触发价与止损价计算的单笔最大亏损（占净值） |
| `confidence` | int | 是 | 0–100，证据充分度；用于分层、展示与门槛，不是涨跌概率 |
| `p_outperform` | number | 是 | 0–1，规则引擎给出的“跑赢基准”概率估计；只用于校准，不向新手展示 |
| `review_date` | date | 是 | 复核日；到期必须复核 |
| `policy_version` | string | 是 | 规则/风控/费用版本 |
| `status` | enum | 是 | `draft` / `active` / `triggered` / `executed` / `invalidated` / `expired` / `reviewed` |
| `model_meta` | object | 否 | LLM 模型、提示词版本、耗时、成本；仅叙述层 |

### 6.3 立场与意图的约束

| 立场 | 含义 | 允许意图 | 新手看到的文案 |
|---|---|---|---|
| 观察 | 有关注价值，但条件不成熟 | `none` | “先看着，今天不动” |
| 候选 | 证据与触发条件基本成立 | `buy` / `add` / `none` | “可以考虑，等触发再买” |
| 谨慎 | 有持仓但风险上升，或新买入不划算 | `reduce` / `exit` / `none` | “先别加，考虑减一点” |
| 回避 | 证据不足、风险过高、流动性差 | `exit` / `none` | “不碰；有持仓则考虑退出” |

**硬约束：**

- 没有 `trigger` 和 `invalidation` 的卡不能进入 `active`。
- 没有至少一条反证的卡不能进入 `candidate`。
- `confidence < 50` 的卡不得给出 `buy` 意图。
- 单卡 `max_position_pct` 不得超过风控上限；超过则卡无效，不是“截断后照发”。
- 每张卡必须能一键展开到证据和快照；不能只给结论。

### 6.4 决策引擎与 LLM 的分工

**确定性引擎负责：**

- 市场状态（趋势、宽度、成交额、波动）。
- 行业相对强弱、政策事件匹配、个股趋势与流动性过滤。
- 评分、排序、仓位上限、触发价、止损价、风控检查。
- `p_outperform`：按版本化映射/校准表计算，不采用 LLM 自报概率。
- 生成结构化字段；同一输入 + 同一规则版本 = 同一输出。

**LLM 负责：**

- 把结构化证据归纳成 ≤80 字的人话结论。
- 解释“如果发生 X，会怎样”的情景。
- 生成复盘叙述、周报摘要。
- 不得修改评分、仓位、触发价、止损价；不得新增未在证据表中的事实。

**MVP 决策规则（透明、可复现）：**

1. **市场闸门**：指数趋势 + 市场宽度 + 成交额。市场状态为“ risk-off”时，只允许减仓/回避，不生成新的买入卡。
2. **行业筛选**：政策/事件强度 + 行业 20 日相对强弱 + 行业成交额占比变化；最多选 3 个行业。
3. **个股筛选**：行业内的趋势（20/60 日均线）、量能（5 日均量/20 日均量）、流动性（20 日 ADV）、事件（公告/政策映射）；排除 ST、停牌、上市不足 60 日、ADV 不足。
4. **证据门槛**：至少 1 条政策/行业证据 + 1 条价格/量能证据 + 1 条反证；否则降为“观察”。
5. **仓位**：按波动率倒数分配，单票不超过 20%，行业不超过 40%，现金不低于 5%。
6. **触发**：突破/回踩/事件确认三类，必须写清价格或日期；未触发不下单。
7. **证伪**：跌破止损、政策逻辑被否、行业相对强弱反转、数据质量 fail；任一触发即复核。

规则参数放在 `policy_versions`，带生效日期和哈希；不在代码里散落魔法数字。

## 7. 纸面账户与账本

### 7.1 账户隔离

- 新建 `paper_accounts`，不复用现有 `positions` 的实盘/手工持仓。
- 每个实验一个账户：`paper-<experiment-id>`；默认实验 `paper-main`。
- 初始虚拟资金：¥200,000（可配置；实验开始后不可修改）。
- 账户状态：`active` / `paused` / `closed`；`closed` 后只读。
- 现有 `portfolio_accounts` 继续服务“手动记录的真实持仓”，模拟盘页面明确区分“真实记录”和“模拟盘”，不混算。

### 7.2 账本原则

- 金额一律整数分；股数一律整数股；价格用分或厘，禁止浮点累加。
- 复式记账：每笔成交同时写现金流水和持仓变动；任何时点满足：

```
现金余额 + 持仓市值 = 账户净值
期初资金 + 累计盈亏 - 累计费用 - 累计税费 + 累计分红 = 期末净值
```

- 所有写操作带幂等键；同一请求重复提交只产生一笔成交。
- 账本只追加，不物理删除；冲正用反向流水。
- 每个交易日收盘后自动对账；对账失败冻结账户并告警。

### 7.3 数据表

### 7.4 订单状态机

```
draft → submitted → accepted → filled
                  ↘ rejected
                  ↘ expired
                  ↘ canceled
```

- `submitted`：用户确认，写入幂等键。
- `accepted`：通过风控，等待撮合。
- `filled`：全部成交（MVP 不做部分成交）。
- `rejected`：风控/停牌/涨跌停/缺价/数据 fail；必须带原因码。
- `expired`：目标交易日收盘仍未成交；不自动顺延。
- `canceled`：用户在截止前撤销；已成交不可撤。

**原因码（新手可读）：**

| 码 | 文案 |
|---|---|
| `RISK_POSITION_CAP` | 这只股票会超过单票上限 |
| `RISK_INDUSTRY_CAP` | 这个行业会超过行业上限 |
| `RISK_CASH` | 现金不够（含费用） |
| `RISK_DAILY_LOSS` | 今天亏损已达上限，暂停买入 |
| `RISK_DRAWDOWN` | 组合回撤触发暂停 |
| `RISK_T1` | 今天买的股票明天才能卖 |
| `LIMIT_UP` | 开盘涨停，买不到 |
| `LIMIT_DOWN` | 开盘跌停，卖不出 |
| `SUSPENDED` | 停牌，无法成交 |
| `MISSING_PRICE` | 缺少开盘价，今天不成交 |
| `DATA_QUALITY` | 数据质量不通过，暂停交易 |
| `ODD_LOT` | 卖出零股必须一次卖完 |

## 8. 纸面撮合规则（A 股）

### 8.1 适用范围

- MVP 股票池：用户自选 + 系统候选池，最多 50 只；仅限沪深主板、创业板、科创板中规则可编码的标的。
- 排除：ST/*ST、退市整理、上市不足 60 个交易日、停牌、ADV 不足、北交所（首期不纳入）。
- 仅做多；不支持融资融券、卖空、杠杆、ETF、可转债、期权。

### 8.2 委托类型

| 类型 | 行为 | MVP |
|---|---|---|
| 开盘市价（`open_market`） | 以目标日开盘价 + 滑点成交 | 支持 |
| 限价（`limit`） | 买入：当日最低价 ≤ 限价才成交；卖出：当日最高价 ≥ 限价才成交 | 支持 |
| 盘中市价 | 依赖分钟线 | 不支持 |
| 止损/止盈条件单 | 依赖盘中触发 | 不支持（用决策卡触发 + 次日开盘） |

### 8.3 撮合算法

**开盘市价买入：**

1. 检查停牌、数据质量、涨跌停、T+1、现金、仓位、行业、流动性。
2. 若开盘价 ≥ 涨停价 → `LIMIT_UP`，不成交。
3. 成交价 = `open * (1 + slippage)`，向上取整到分；不得超过涨停价。
4. 数量按 100 股整数倍向下取整；科创板按 200 股起、1 股递增；创业板/主板 100 股整数倍。
5. 费用 = 佣金 + 过户费；买入不收印花税。
6. 现金扣减 = 成交金额 + 费用；若不足 → `RISK_CASH`。

**开盘市价卖出：**

1. 检查 `available_shares`（T+1）、停牌、跌停、数据质量。
2. 若开盘价 ≤ 跌停价 → `LIMIT_DOWN`，不成交。
3. 成交价 = `open * (1 - slippage)`，向下取整到分；不得低于跌停价。
4. 费用 = 佣金 + 印花税 + 过户费。
5. 零股必须一次卖完；否则 `ODD_LOT`。

**限价单：**

- 买入：若当日 `low <= limit_price`，成交价 = `min(open * (1 + slippage), limit_price)`；若开盘即涨停且 `open >= limit_up`，不成交。
- 卖出：若当日 `high >= limit_price`，成交价 = `max(open * (1 - slippage), limit_price)`；若开盘即跌停且 `open <= limit_down`，不成交。
- 无法判断当日是否触及时（缺 high/low），拒绝，不猜。

**成交时点：** 统一记为 `09:25` 集合竞价成交；UI 显示“按开盘价纸面成交”，不伪装成盘中实时成交。

### 8.4 费用（默认，可配置）

| 费用 | 默认 | 方向 | 说明 |
|---|---|---|---|
| 佣金 | 成交额 × 0.025%，最低 ¥5 | 买/卖 | 可配置；不同券商不同 |
| 印花税 | 成交额 × 0.05% | 卖 | 按现行税率；政策变化时更新版本 |
| 过户费 | 成交额 × 0.001% | 买/卖 | 沪深统一口径，按最新规则 |
| 滑点 | 成交价 × 0.05% | 买/卖 | 买入加、卖出减；可用固定值或“1 个最小价位取大” |

- 所有费用按分取整，规则写入 `paper_policy_versions`。
- 费用假设必须保守；宁可高估成本，不低估。
- 每次费率变化新建版本，历史成交不重算。

### 8.5 T+1 与可用数量

- 买入成交后：`total_shares += qty`；`available_shares` 不增加。
- 下一个交易日开盘前：`available_shares = total_shares`（除当日新买入）。
- 卖出只能卖 `available_shares`；卖出后 `total_shares` 和 `available_shares` 同减。
- 卖出所得现金当日可用于买入（A 股资金 T+0 可用），但提现 T+1 的概念在模拟盘中不需要。

### 8.6 停牌、涨跌停、除权除息

- **停牌**：不撮合；已有委托 `rejected(SUSPENDED)` 或 `expired`；持仓按最近收盘价估值并标 `stale`。
- **涨跌停**：按板块/ST/新股规则取当日涨跌停价；不得统一按 10%。开盘触及涨停的买单不成交，开盘触及跌停的卖单不成交；不模拟排队。
- **分红**：除息日现金入账 = 持股数 × 每股分红；按 **FIFO 批次**的持有期代扣红利税（≤1 个月 20%，1 个月–1 年 10%，>1 年 0），税率写入政策版本。未实现批次时不得默认按 0 税率高估收益；至少按 10% 保守预扣并在复盘标注。
- **送转/拆股**：按比例调整各批次股数与每股成本；零股按规则处理。
- **卖出成本**：按 FIFO 从最早未平批次扣减，`paper_lot_closes` 记录每笔已实现盈亏与持有天数；胜率、盈亏比、利润因子均以此为准，不用移动平均成本倒推。
- **配股/增发/合并**：MVP 不自动处理；标记 `unhandled_corporate_action`，暂停该标的新委托，要求人工复核后记账。
- **退市**：标记 `delisted`；停止新委托；持仓按最后可得价格估值并标 `stale`，在复盘中要求人工确认减值，不伪造退出价。

### 8.7 估值

- 持仓市值 = Σ(可用数量 + 冻结数量) × 最新收盘价；缺价时不计入市值，列入 `missing_codes`，不得按 0 计算。
- 账户净值 = 现金 + 持仓市值。
- 当日收益 = 当日净值 / 前一日净值 - 1；无前一日净值时为空，不填 0。
- 基准：现金（0%）、沪深 300、中证 500、等权自选；每个基准单独展示，不混成一条“基准”。
- 复权：估值用未复权价 + 公司行动；绩效用复权净值。两套口径不得混用。

## 9. 风控引擎

### 9.1 原则

- 风控是硬约束，不是提示；不通过就不生成委托。
- 风控在“卡生成”和“委托提交”两处都检查；任一失败即拦截。
- 所有拦截可解释、可追溯、可复核；不允许“静默降级”。
- 参数锁定在 `paper_policy_versions`；修改需新版本并记录原因。

### 9.2 MVP 规则

| 规则 | 默认阈值 | 动作 |
|---|---|---|
| 单票上限 | 净值 20% | 拦截加仓 |
| 行业上限 | 净值 40% | 拦截加仓 |
| 最大持仓数 | 5 只 | 拦截新开仓 |
| 单日新开仓 | 1 只 | 拦截 |
| 单日委托数 | 3 笔 | 拦截 |
| 现金缓冲 | 净值 5% | 拦截 |
| 单笔最大亏损 | 净值 2% | 拦截或缩小仓位（MVP 直接拦截，不自动缩） |
| 单日亏损 | 净值 2% | 当日禁止新买入 |
| 组合回撤 | 峰值回撤 10% | kill switch：禁止新买入，要求人工复核 |
| 流动性 | 20 日 ADV ≥ ¥5,000 万；持仓 ≤ ADV 5% | 拦截 |
| 停牌/ST/退市/新股 | 排除 | 拦截 |
| T+1 | 当日买入不可卖 | 拦截 |
| 数据质量 | `fail` | 全局禁止交易 |
| 对账 | 日终不平衡 | kill switch |

### 9.3 Kill switch

- 触发条件：回撤超限、对账失败、数据质量 fail、连续 3 日无法估值、人工按下。
- 行为：停止所有新委托；已有持仓只允许减仓（如果数据可用）；页面顶部红色横幅（图标 + 文案，不只靠颜色）；通知任务中心。
- 解除：必须由用户填写原因、完成一次复盘、确认数据恢复；解除记录进审计日志。
- 不得自动解除。

### 9.4 风控事件

- 每条事件包含：规则、阈值、实际值、动作、相关订单/卡、时间。
- 新手文案示例：“这笔买入会让白酒行业占到组合的 43%，超过 40% 上限，所以没有执行。”
- 事件不删除；误报也要保留并标注。

## 10. 复盘与评估

### 10.1 每日复盘

收盘后自动生成，包含：

1. 今日是否有操作；如果没有，为什么（无卡/未触发/风控/数据）。
2. 成交明细：买卖、价格、数量、费用、滑点。
3. 净值变化、基准变化、超额。
4. 风险事件与违规。
5. 持仓变化与集中度。
6. 明日待办：到期复核、触发条件、数据修复。

### 10.2 每周复盘

- 周收益、超额、最大回撤、波动、成交次数、换手、费用拖累。
- 决策质量：卡片证据完整度、触发/证伪是否预先写清、是否按计划执行。
- 行为质量：是否追涨、是否频繁改计划、是否忽略证伪、是否超仓。
- 数据质量：缺失、延迟、冲突、修复情况。
- 下周关注：候选池、行业变化、政策日历。

### 10.3 决策结果评估

每张卡在 5/20/60 个交易日（按 `horizon`）评估：

| 字段 | 说明 |
|---|---|
| `return_pct` | 从触发价/决策价到评估日的复权收益 |
| `benchmark_return_pct` | 同期基准收益 |
| `alpha_pct` | 超额 |
| `max_adverse_pct` | 期间最大不利变动（MAE） |
| `hit` | 是否跑赢基准（主口径）；另记是否盈利 |
| `reason_class` | `right_reason` / `right_luck` / `wrong_reason` / `wrong_luck` / `not_triggered` |
| `invalidation_hit` | 是否触发证伪条件 |
| `notes` | LLM 归纳 + 用户备注 |

**“对错”不只看盈亏：**

- 判断对、执行对、赚钱 → 可复制。
- 判断对、执行错、赚钱 → 运气，不可复制。
- 判断错、执行对、亏小钱 → 可接受，记录教训。
- 判断错、执行错、亏大钱 → 红线，必须复盘。

### 10.4 有效性指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 累计收益 | 期末净值 / 期初净值 - 1 | 总览 |
| 年化收益 | 按 252 日折算；不足 1 年标注“未年化” | 对比 |
| 超额收益 | 组合收益 - 基准收益 | 核心 |
| 最大回撤 | 日净值峰谷最大跌幅 | 风险 |
| 夏普 | (日均收益 − 无风险利率) / 日收益标准差 × √252；默认无风险利率 0，标注 | 风险调整 |
| 索提诺 | 只用下行波动 | 下行风险 |
| 胜率 | 盈利平仓交易 / 总平仓交易 | 交易层面 |
| 决策命中率 | 跑赢基准的到期卡 / 到期卡 | 决策层面 |
| 盈亏比 | 平均盈利 / 平均亏损 | 交易层面 |
| 利润因子 | 总盈利 / 总亏损 | 交易层面 |
| 换手率 | 买卖金额 / 平均净值，年化 | 成本 |
| 费用拖累 | 佣金+印花税+过户费+滑点 / 平均净值，年化 | 成本 |
| 集中度 | 前三大持仓权重、HHI | 风险 |
| Brier 分数 | 用卡片 `p_outperform` 作为“跑赢基准”的概率预测，与实际二值结果求平均平方误差；不得拿展示用的 `confidence` 顶替 | 校准 |
| 状态分组 | 按牛/熊/震荡、行业、市值、波动分组 | 稳健性 |
| 压力测试 | 历史极端区间回放、成本翻倍、滑点翻倍、延迟一天成交 | 韧性 |

**统计纪律：**

- 少于 120 个交易日或 30 张到期卡，只做描述性统计，不宣称“有效”。
- 少于 250 个交易日或 100 张到期卡，不做显著性结论；可给 bootstrap 置信区间，但必须标注样本不足。
- 不挑时间段、不删亏损样本、不按结果调参数；所有版本保留。
- 评估窗口开始前锁定基准、指标、阈值；开始后修改视为新实验。

### 10.5 自动化准入评分卡

L1 → L2 之前锁定，总分 100：

| 维度 | 分值 | 通过要求 |
|---|---|---|
| 数据与运维 | 25 | 数据可用率 ≥ 99%；对账 100% 平衡；无前视审计失败；重大事故 ≤ 1 次且已修复 |
| 决策过程 | 20 | 卡片字段完整率 100%；规则版本未漂移；每张卡有反证；证据可追溯 |
| 绩效 | 20 | 扣费后超额 > 0；最大回撤 ≤ 10%；夏普 > 0.5（样本不足时标注观察） |
| 校准 | 10 | Brier 分数优于“全部按基准概率”的基线 |
| 执行 | 10 | 成交/拒绝原因可解释；无重复成交；无未对账差异 |
| 行为 | 10 | 按计划执行率 ≥ 90%；无超仓/无未经复核的 kill switch 解除 |
| 合规 | 5 | 免责声明、数据许可、审计日志齐全；无真实委托能力 |

**门槛：** 总分 ≥ 80，且“数据与运维”“合规”不得低于 80%；否则不进入 L2。门槛在实验开始前写入 `paper_policy_versions`，不得中途下调。

## 11. 技术架构

### 11.1 模块边界

```
数据接入层
  ├─ source adapters（Tushare / 交易所 / 巨潮 / 新闻 / 延迟报价）
  ├─ 数据质量检查
  └─ PIT 快照构建
        ↓
决策层
  ├─ 市场状态
  ├─ 行业筛选
  ├─ 个股筛选
  ├─ 决策卡生成（确定性规则）
  └─ LLM 叙述（只读结构化证据）
        ↓
风控层
  ├─ 卡级风控
  ├─ 委托级风控
  └─ kill switch
        ↓
执行层
  ├─ ExecutionGateway（接口）
  │    ├─ PaperGateway（本期）
  │    ├─ BrokerSandboxGateway（未来）
  │    └─ LiveGateway（更远）
  ├─ 纸面撮合
  └─ 账本
        ↓
复盘层
  ├─ 每日对账
  ├─ 每日/每周复盘
  ├─ 决策结果评估
  └─ 指标与报告
```

### 11.2 `ExecutionGateway` 接口（本期只实现 Paper）

```ts
interface ExecutionGateway {
  submit(order: PaperOrderInput): Promise<ExecutionResult>
  cancel(orderId: string): Promise<ExecutionResult>
  getOrder(orderId: string): Promise<OrderSnapshot>
  getFills(orderId: string): Promise<FillSnapshot[]>
  reconcile(date: string): Promise<ReconcileReport>
}
```

- 本期只有 `PaperGateway`；不得在代码中直接调用任何券商 SDK。
- 未来 `BrokerSandboxGateway` / `LiveGateway` 必须复用同一接口和同一风控前置。

### 11.3 调度

- 复用现有单 worker 任务队列；新增任务类型：
  - `paper_preopen`（08:30）
  - `paper_decide`（08:45）
  - `paper_open_fill`（09:25）
  - `paper_intraday_monitor`（交易时段每 5 分钟，仅风险提示）
  - `paper_close`（15:05）
  - `paper_reconcile`（16:10）
  - `paper_evaluate`（17:00）
  - `paper_weekly_review`（周六 10:00）
- 所有任务幂等；重跑不重复成交、不重复记账。
- 交易日历守卫：非交易日直接跳过，不生成空报告。
- Web 无常驻调度时，页面明确提示“自动任务未运行”，并提供手动触发；不得假装已运行。

## 14. 验收标准

### 14.1 功能验收

- [ ] 新建纸面账户，初始资金 ¥200,000，现金流水平衡。
- [ ] 生成一张决策卡，包含 ≥3 条证据、≥1 条反证、触发、证伪、仓位、复核日、快照 ID。
- [ ] 用户确认后生成委托；未确认不成交。
- [ ] 次日开盘按规则成交；成交价、费用、滑点可解释。
- [ ] 买入当日不可卖；次日可卖。
- [ ] 开盘涨停买单不成交；开盘跌停卖单不成交；停牌不成交。
- [ ] 缺开盘价拒绝成交，不顺延猜测。
- [ ] 分红/送转后账本平衡；未处理公司行动被标记并暂停该标的。
- [ ] 日终对账平衡；不平衡触发 kill switch。
- [ ] 风控拦截有具体规则、实际值、新手文案。
- [ ] 净值、基准、超额、回撤、费用拖累可查看。
- [ ] 决策卡到期后生成结果评估；未到期不伪造结果。
- [ ] 示例数据与真实数据不混用；示例水印可见。
- [ ] 非交易日显示“休市”，不生成空报告。

### 14.2 数据与审计验收

- [ ] 每张卡绑定不可变快照；快照可追溯到源文档和行情版本。
- [ ] 注入未来公告/K线，决策与评估不变（前视审计通过）。
- [ ] 重复提交同一委托只产生一笔成交（幂等）。
- [ ] 所有写操作有审计日志；日志不含密钥。
- [ ] 数据源失败时显示降级原因，不用旧数据冒充今日数据。
- [ ] 模拟盘无任何券商 SDK/真实下单代码路径。

### 14.3 新手可用性验收

- [ ] 新用户 30 秒内能说出“今天要不要动、为什么”。
- [ ] 一张卡的首屏能回答：买什么、为什么、买多少、最多亏多少、何时复核。
- [ ] 不展开抽屉也能看到风险与反证；展开后能看到证据与快照。
- [ ] 任何拦截/失败都有“下一步怎么办”，不是只报错。
- [ ] 移动端单手可完成“看卡 → 确认 → 查看结果”。
- [ ] 术语有内联解释；不出现“夏普/索提诺/Brier”等词而不解释。

### 14.4 性能与可靠性

- [ ] 决策卡生成 ≤ 60 秒（50 只股票池，缓存命中时 ≤ 15 秒）。
- [ ] 开盘撮合 ≤ 10 秒完成全部委托。
- [ ] 日终对账 ≤ 30 秒。
- [ ] 页面首屏（模拟盘总览）≤ 2.5 秒（本地/局域网）。
- [ ] 任务失败可重试；重试不重复成交/记账。

## 15. 风险、假设与待确认

### 15.1 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 免费数据不稳定/封 IP | 决策与估值中断 | 多源降级、质量门、显式提示；不绕过限制 |
| 涨跌停/板块规则复杂 | 成交假设失真 | 规则表 + 测试夹具；不支持板块先排除 |
| 公司行动遗漏 | 净值错误 | 每日检查、标记未处理、暂停该标的 |
| 小样本过度解读 | 误判“有效” | 统计纪律、置信区间、阶段门 |
| 用户把模拟当实盘 | 行为风险 | 固定横幅、虚拟资金标识、无真实下单入口 |
| LLM 幻觉 | 错误叙述 | 确定性字段 + 证据白名单 + 叙述只读 |

### 15.2 默认假设（可评审调整）

- 初始虚拟资金：¥200,000。
- 股票池：自选 + 系统候选，最多 50 只。
- 仅沪深主板/创业板/科创板；排除北交所、ST、退市整理、上市不足 60 日。
- 每笔纸面委托需用户确认；不自动执行。
- 只做收盘/盘前决策，次日或当日开盘成交；不做盘中。
- 费用按第 8.4 节默认值；可按用户券商调整，但需新版本。
- 绩效主口径为“扣费后相对沪深 300 的超额”，同时展示中证 500 与等权自选。

### 15.3 需要产品确认的问题

1. 初始资金是否用 ¥200,000，还是让用户在首次启动时选择（建议给 3 档：10 万/20 万/50 万）？
2. 股票池是否允许用户手动加入任意 A 股，还是只允许系统候选 + 自选（建议后者，控制数据与复杂度）？
3. 是否允许用户修改单票/行业上限（建议 MVP 只读，避免新手把风控调没）？
4. 纸面委托是否每笔都要确认（建议是；后续可加“自动执行已批准计划”，但仍需阶段门）？
5. 是否需要“模拟盘 vs 真实手动持仓”对比视图（建议 P1，避免首屏复杂）？
6. 分红税是否按持有期模拟（建议是；若不做，必须显示“未扣红利税”，不能静默高估）？

## 17. 附：关键不变量

实现和评审时，以下不变量不得破坏：

1. **没有快照，不发卡。**
2. **没有触发和证伪，不发卡。**
3. **没有反证，不买。**
4. **没有用户确认，不成交。**
5. **没有开盘价，不成交。**
6. **数据 fail，不交易。**
7. **账本不平，不继续。**
8. **示例数据，不混真。**
9. **LLM 不碰数字，不碰仓位，不碰委托。**
10. **模拟盘没有任何真实下单路径。**
